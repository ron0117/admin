## 2. 总体架构

```text
浏览器 Admin
  ├─ 登录 ──► POST /admin/auth/login     （查 AdminUser）
  ├─ nestRequest（已有）
  ├─ views/manage/admin  ──► /admin/admins*
  └─ views/manage/user   ──► /admin/users*   （仅 Electron User，无 role）

Nest
  ├─ AuthModule            /auth/*              JWT_SECRET，只认 User
  ├─ AdminAuthModule       /admin/auth/*        JWT_ADMIN_SECRET，只认 AdminUser
  ├─ AdminsModule（新）    /admin/admins*       JwtAdminAuthGuard
  ├─ AdminUsersModule      /admin/users*        JwtAdminAuthGuard（去掉 RolesGuard / role 字段）
  └─ seed                  upsert AdminUser
```

**JWT**

| | Electron | 后台 |
|--|----------|------|
| 路径 | `/auth/*` | `/admin/auth/*` |
| 密钥 | `JWT_SECRET` | `JWT_ADMIN_SECRET` |
| aud | 无 | `admin` |
| sub | `User.id` | `AdminUser.id` |
| refresh 存储 | `RefreshToken.userId` → User | `AdminRefreshToken.adminUserId` → AdminUser |

两边 token **互验失败**（401）。同邮箱可以各有一条记录，密码独立。

## 4. 关键流程

### 4.1 后台登录（替换主体）

```text
POST /admin/auth/login { email, password }
  → AdminUser.findUnique(email.lower)
  → 无记录 / 密码错 → 401 AUTH_FAILED（防枚举，不区分「不是管理员」）
  → status=disabled → 403 ACCOUNT_DISABLED
  → 签发 access（sub=adminUserId, aud=admin）+ 写入 AdminRefreshToken
```

Electron `POST /auth/login` **不读** `AdminUser`。仅有管理员表记录时 `/auth/login` 为 401。

### 4.2 管理员 CRUD

```text
列表  GET    /admin/admins?page&pageSize&keyword&status
创建  POST   /admin/admins          { email, password, username? } → active
更新  PATCH  /admin/admins/:id      { username?, email?, status?: active|disabled }
重置  POST   /admin/admins/:id/reset-password  { password }
```

禁用或重置 → `AdminRefreshToken` 对该 `adminUserId` 全部 `revokedAt=now()`。

保护（写路径，事务内计数）：

- `id === actor.adminUserId` 且试图 `status=disabled` → 403 `CANNOT_MODIFY_SELF`
- 禁用后 active 管理员数将变为 0 → 403 `LAST_ADMIN`

无「降级」：管理员表没有 role。

### 4.3 用户管理收敛

`/admin/users*` 仍操作 `User`。去掉 DTO 的 `role`；列表不再返回 `role`（或固定不展示）。创建默认 `UserRole.user`（列暂留）。不再做 LAST_ADMIN / 禁自己（自己是 `AdminUser`，不会等于 `User.id`）。

Electron 用户仍可 `pending_verification`；管理员表无此状态。

### 4.4 Seed / 存量

```text
npx prisma db seed
  → 按 ADMIN_SEED_EMAIL 在 AdminUser upsert（active + 新密码哈希）
  → 不更新、不创建 User
```

本地若以前 seed 过 `User.role=admin`：该行仍只是 Electron 用户，**不能**再后台登录，除非另有 `AdminUser`。README 写明。

## 5. 数据模型

```prisma
enum AdminUserStatus {
  active
  disabled
}

model AdminUser {
  id            String              @id @default(uuid()) @db.Uuid
  email         String              @unique
  username      String?             @unique
  passwordHash  String
  status        AdminUserStatus     @default(active)
  createdAt     DateTime            @default(now())
  updatedAt     DateTime            @updatedAt
  refreshTokens AdminRefreshToken[]
}

model AdminRefreshToken {
  id          String     @id @default(uuid()) @db.Uuid
  adminUserId String     @db.Uuid
  adminUser   AdminUser  @relation(fields: [adminUserId], references: [id], onDelete: Cascade)
  tokenHash   String     @unique
  expiresAt   DateTime
  revokedAt   DateTime?
  createdAt   DateTime   @default(now())

  @@index([adminUserId])
  @@index([expiresAt])
}
```

公开字段（响应禁止 `passwordHash`）：`id, email, username, status, createdAt, updatedAt`。

`User` / `RefreshToken` / `UserRole` **不删**。后台 refresh **不再**写入 `RefreshToken`，可废弃 `admin:` 哈希前缀（改走独立表）。历史上用 `admin:` 前缀写在 `RefreshToken` 上的行可忽略，随用户禁用/过期自然失效。

bcrypt rounds = 10，与现网一致。

## 6. 接口

鉴权：全部 `/admin/admins*` 与现有 `/admin/users*`、`/admin/auth/me|logout` 使用 `JwtAdminAuthGuard` + Bearer `JWT-Admin`。

### 6.1 `/admin/admins`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/admin/admins` | `{ items, total, page, pageSize }` |
| POST | `/admin/admins` | 创建，直接 active |
| PATCH | `/admin/admins/:id` | 用户名 / 邮箱 / 状态 |
| POST | `/admin/admins/:id/reset-password` | 新密码 + 撤 refresh |

错误码沿用 `AuthException`：`EMAIL_TAKEN` 409、`USERNAME_TAKEN` 409、`USER_NOT_FOUND` 404（文案可用「管理员不存在」）、`CANNOT_MODIFY_SELF` 403、`LAST_ADMIN` 403、`INVALID_STATUS` 400、`AUTH_FAILED` 401。

### 6.2 `/admin/auth` 行为变化

| 项 | 现状 | 目标 |
|----|------|------|
| login 查表 | `User` + `role=admin` | `AdminUser` |
| 非管理员登录 | 403 FORBIDDEN | 无 `AdminUser` 时 **401 AUTH_FAILED**（与错密码相同，防枚举） |
| me / refresh | `User` + `RefreshToken`（admin 前缀） | `AdminUser` + `AdminRefreshToken` |
| JWT sub | `User.id` | `AdminUser.id` |

登录响应形状保持 `{ user, accessToken, refreshToken, expiresIn }`，`user` 无 `role` 字段（或忽略）。Admin 前端 `mapNestUserToBoUser`：无 role 时 `accountType` 固定为超级管理员文案。

### 6.3 `/admin/users` 行为变化

去掉 query/body 的 `role`。创建强制 `role=user`。禁自己 / LAST_ADMIN 从本模块删除。激活 pending、禁用 Electron 用户、撤 **User** 的 `RefreshToken` 保留。

## 7. 技术选型与备选

| 点 | 选用 | 不选 |
|----|------|------|
| 身份存储 | 独立 `AdminUser` | 继续 `User.role`；或单表加 `client` 字段 |
| 后台 refresh | `AdminRefreshToken` | 共用 `RefreshToken` + 可空 `userId` |
| 后台鉴权 | 仅 `JwtAdminAuthGuard` | 再套 `RolesGuard` |
| 存量数据 | 不自动迁移 | 脚本把 `User.role=admin` 复制进 `AdminUser`（邮箱冲突难处理） |

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 未 migrate / 未重新 seed，后台全员登不上 | README + 计划 M0 先迁移再改登录；e2e 用内存 mock 两表 |
| `AuthUser.userId` 与 `AdminUser.id` 混用去 PATCH `/admin/users/:id` | 类型拆成 `AdminAuthUser.adminUserId`；用户管理禁自己逻辑删除 |
| Admin 前端仍按 `user.role==='admin'` 映射 | 登录映射改为「能登录即管理员」 |
| 旧后台 JWT（sub 为 User.id）在发布后短窗口 | access TTL 默认 1h；refresh 换表后旧 refresh 全部失效，需重新登录 |
