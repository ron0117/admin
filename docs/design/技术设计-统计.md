## 1. 目标与约束

| 项 | 内容 |
|----|------|
| 目标 | 「积分」下新增积分统计页；首页三张 ECharts 与统计页默认窗口数字一致 |
| 基座 | JQ* + `nestRequest`；`echarts` 6 + `useEcharts`；dayjs 默认时区已是上海 |
| 约束 | 不改 `request/shared.ts`；不新引入图表库；不在首页做筛选和表格 |
| 非目标 | 导出、充值/调账/余额图、规格下钻、标题跳转统计页、Electron |

| 维度 | 结论 | 说明 |
|------|------|------|
| 数据 | Go | 只读 `PointLedger` / `Role` / `PointFeature`，不改表 |

| 路由 | Go | `views/points/stats/index.vue` → elegant `points_stats` |

**门禁：Go。** 阻塞项只有 Nest 两个只读接口。

## 4. 时间

预设在浏览器里用 `dayjs.tz()` 算上海自然日，再格式化成与流水页相同的 `YYYY-MM-DD HH:mm:ss.SSS`（`ADMIN_DATETIMERANGE_VALUE_FORMAT`）。不要用无时区的 `dayjs()`，避免操作者电脑不是东八区时窗口偏一天。

| 预设 | from | to |
|------|------|----|
| 近 7 天 | 今天往前共 7 个自然日的 00:00:00.000 | 今天 23:59:59.999 |
| 近 30 天 | 共 30 个自然日，默认 | 同上 |
| 近 90 天 | 共 90 个自然日 | 同上 |
| 全部 | 不传 | 不传 |
| 自定义 | 日期起 00:00:00.000 | 日期止 23:59:59.999 |

工具放在 `src/utils/time.ts`：`getShanghaiRecentDaysRange(days)`，供首页和统计页共用。

首页写死 30。统计页改预设时，汇总接口和用户表一起换 `from`/`to`。自定义止日早于起日：不发请求，沿用上一次成功结果，并提示「结束日期不能早于开始日期」。

## 5. 积分统计页

`JQCustomPage`。筛选一行：预设 `select`（近 7 / 30 / 90 / 全部 / 自定义）。选自定义时再出一个日期范围（`daterange`，不是时刻）。角色卡片标题下固定一句说明：「按用户当前绑定的角色统计，多名角色会重复计入。」

三块都是上图下表。用户表 `JQDataTable` 分页；角色、功能不分页。

### 5.1 图

| 块 | 组件 | 数据 |
|----|------|------|
| 用户 | `UserConsumeBar` | `byUser`（已是 Top 10） |
| 角色 | `RoleConsumeBar` | `byRole` |
| 功能 | `FeatureConsumePie` | `byFeature` 里 `netPoints > 0`；中心用响应里的 `total` |

`total === 0` 时该块用空态「该时间范围内没有已完成的积分消耗」，不初始化空图。

### 5.2 用户表

`GET /admin/points/stats/users`。列：用户名（空则邮箱）、邮箱、当前角色（顿号拼接，无角色写「未分配角色」）、净消耗、笔数。关键字搜邮箱/用户名，回车或查询按钮触发，页码回到 1。默认 `pageSize` 20。只显示净消耗 > 0，服务端已过滤。

### 5.3 角色表

用汇总里的 `byRole`。列：角色、状态（`active` 启用 / `disabled` 已禁用；未分配行状态为「—」）、净消耗、有消耗用户数。**没有占比列。**

### 5.4 功能表

用汇总里的 `byFeature`，含 0。列：功能、净消耗、笔数、占本期总消耗。占比由前端用该行 `netPoints / total` 计算；`total === 0` 时全部显示 `0%`。展示保留 1 位小数。最后一行用「100% 减去前面已展示的和」吸收四舍五入，保证加总是 100%。未知功能 `known === false` 时名称用接口的 `name`。

## 6. 首页

`views/home/index.vue`：

- `HeaderBanner` 不动。
- 去掉 `ContentInfo` 欢迎大卡片。
- 第一行：用户柱 `lg=14`，角色柱 `lg=10`。第二行：功能环 `lg=12`。`xs=24` 上下堆叠。
- 每张卡片标题为「按用户 / 按角色 / 按功能」，副标题「近 30 天净消耗」。角色卡同样带 §5 那句重复计入说明。
- 进入页面请求一次汇总。失败时三张卡都显示请求失败，不留欢迎文案充数。

## 7. 图表选项

走 `useEcharts`。类目过长：轴上截到 12 字，`tooltip` 给全名。

| 图 | 选项要点 |
|----|----------|
| 用户柱、角色柱 | `yAxis.type = category`，`inverse: true`（大的在上）；`xAxis.type = value`；`barMaxWidth: 16`；网格左侧留名 |
| 用户 tooltip | 用户名、邮箱、净消耗、笔数 |
| 角色 tooltip | 角色名、净消耗、有消耗用户数；未分配不显示状态 |
| 功能环 | `radius: ['48%', '70%']`；`title` 居中，主文案 `total`，副文案「净消耗」；图例放右侧，项为「名称 积分」 |

用户柱的类目用 `displayName`。颜色用 ECharts 默认色板，不单独做主题。

## 9. 风险与对策

| 风险 | 对策 |
|------|------|
| 浏览器时区把「近 30 天」算偏 | 只用 `dayjs.tz()` |
| 首页和统计页各写一套 option，以后改一口径就分叉 | 图组件只放统计页 `modules/`，首页引用 |
| 功能占比四舍五入加总不是 100% | 最后一行补差 |
| 角色图被读成占比 | 柱状图 + 固定说明，表上不放百分比 |
