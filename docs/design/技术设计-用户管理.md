# 技术设计 · 用户管理

> 对齐：[需求-用户管理-梳理版](../detail/需求-用户管理-梳理版.md)  
> 待澄清默认：Q-01 登录接 Nest；Q-02 后台创建即 `active`；Q-03 禁自己/最后 admin 均禁止；Q-04 不物理删除；Q-05 改邮箱为 Should；Q-06 管理员设新密码并撤 refresh；Q-07 Admin 侧 Nest 专用请求客户端；Q-08 菜单 stub 可见、接口拒非 admin；Q-09 可直接激活待验证；Q-10 创建默认角色 `user`

---

## 1. 目标与约束

| 项 | 内容 |
|----|------|
| 目标 | Admin 可对 Nest `User` 做完整管理 CRUD；接口仅 `role=admin` 可调 |
| 技术基座 | Admin：Vue3 + Element Plus + JQ*；Nest：现有 JWT + Prisma `User`，**不改表** |
| 约束 | 不改 `admin/src/service/request/shared.ts`（规则禁止未批准修改）；不恢复 privilege 树；不混用 `/auth/register` |
| 非目标 | RBAC 菜单裁剪、物理删除、`plan`、导出、Electron |

### 1.1 可行性（Go）

| 维度 | 结论 | 说明 |
|------|------|------|
| 数据模型 | Go | `User` / `UserStatus` / `UserRole` 已覆盖列表与启停/角色 |
| 鉴权 | Conditional Go | JWT 策略目前**不加载 `role`**，须扩 `AuthUser` + `RolesGuard` |
| 前后端协议 | Conditional Go | Admin 默认认 `{ code, data }`；Nest 为 HTTP + 裸 JSON。用**独立 Nest 客户端**适配，不改全局 `shared.ts` |
| 登录 | Go | **独立** `POST /admin/auth/*` + `JWT_ADMIN_SECRET`；与 Electron `/auth/*` 令牌隔离 |
| 种子账号 | Go | 现状无 seed；补幂等 seed / 环境变量 |

**门禁：Conditional Go。** 阻塞项均在本设计内消化，无需改 Prisma schema。

## 2. 总体架构

```text
浏览器 Admin
  ├─ 登录页 ──(VITE_AUTH_MOCK=N)──► POST /admin/auth/login
  │                                    └─ 仅 role=admin 且 active；映射为现有 token / userInfo 形状
  ├─ nestRequest（新客户端）
  │     HTTP 2xx 成功；401 先 /admin/auth/refresh 再试；Bearer = localStg.token
  │     开发：Vite 代理 /proxy-nest → http://localhost:3000
  └─ views/manage/user  ──► GET/POST/PATCH /admin/users*
                              POST /admin/users/:id/reset-password

Nest nest-api
  ├─ AuthModule（既有，Electron）  /auth/login|refresh|me|logout
  │     JWT_SECRET；payload 无 aud 或非 admin
  ├─ AdminAuthModule（新）  /admin/auth/login|refresh|me|logout
  │     JWT_ADMIN_SECRET；payload aud=admin；refresh hash 加 admin: 前缀
  ├─ AdminUsersModule
  │     JwtAdminAuthGuard + RolesGuard(admin)
  │     AdminUsersService → Prisma User + 撤 refresh
  └─ prisma/seed.ts（幂等建首个 admin）
```

**契约源：** Nest Swagger `/docs`。`packages/contracts` 仍只服务 Worker/队列，**不**把管理端 DTO 放进去（Admin 自有 `typings/api`）。

## 3. 模块职责

### 3.1 NestJS

| 模块 | 路径（建议） | 职责 |
|------|----------------|------|
| JWT 补齐 | `auth/jwt.strategy.ts`、`auth/decorators/current-user.decorator.ts` | Electron `validate` 增加 `select.role`；`AuthUser` 增加 `role`。**每次请求读库** |
| AdminAuth | `admin-auth/` | 后台独立登录；`JWT_ADMIN_SECRET` + `aud=admin`；仅 `admin`+`active` 可登录 |
| JwtAdminAuthGuard | `admin-auth/jwt-admin-auth.guard.ts` | 校验后台 JWT；桌面端 token → **401**；降级/禁用后立即 401 |
| RolesGuard | `auth/roles.guard.ts` + `@Roles(UserRole.admin)` | 非 admin → **403**（防御纵深）；无后台 JWT → 仍 401 |
| AdminUsers | `admin-users/`（controller / service / dto） | 列表、创建、PATCH、重置密码；安全约束；安全日志 |
| Seed | `prisma/seed.ts` | 用 `ADMIN_SEED_EMAIL` / `ADMIN_SEED_PASSWORD` 幂等确保一名 `admin`+`active` |
| Swagger | `main.ts` | 增加 tag `admin-users` |
| CORS | `main.ts` | 开启 `enableCors({ origin: true })`，避免未走代理时浏览器跨域失败（与 WS 已有 `origin: true` 对齐） |

现有 `/auth/*` **行为不变**（自助注册仍 `pending_verification` + 验证码）。

### 3.2 Admin

| 模块 | 路径（建议） | 职责 |
|------|----------------|------|
| Nest 客户端 | `src/service/request/nest.ts` | 独立 `createFlatRequest`；**不修改** `request/shared.ts`；可复用 `getAuthorization` |
| 登录适配 | `src/service/api/auth.ts` | `VITE_AUTH_MOCK=N` 时打 Nest `/admin/auth/login|refresh|me|logout`，映射到现有 `LoginToken` / `UserInfo` |
| 用户 API | `src/service/api/admin-users.ts` + `typings/api/admin-users.d.ts` | 只从 `@/service/api` 导出 |

| Mock（Could） | `request/mock-handlers.ts` | `VITE_AUTH_MOCK=Y` 时列表可点；验收不以 mock 为准 |
| Env | `.env` | `VITE_NEST_BASE_URL`；联调将 `VITE_AUTH_MOCK=N` |

- 相对 `views/` **两层**：父级菜单「用户管理」、子页「用户列表」

## 4. 关键流程

### 4.1 管理员登录（Q-01）

```text
登录表单 email + password
  → POST /admin/auth/login
  → 仅 role=admin 且 status=active 成功（签发 JWT_ADMIN_SECRET，aud=admin）
  → 普通 user / 桌面端 JWT 不能进此后台会话
  → Admin 存储：
       token        = accessToken
       refreshToken = refreshToken
       userInfo     = 映射后的 Api.Auth.UserInfo
  → 静态路由不过滤 privilege（stub）
```

Electron 继续 `POST /auth/login`（`JWT_SECRET`）。两边 access / refresh **互验失败**（401）。禁用/重置密码仍作废该用户全部 refresh（含两端）。

`GET /admin/auth/me` 用于刷新后的 `initUserInfo`。`POST /admin/auth/refresh` 替换现有 `fetchRefreshToken`（非 mock 时）。

**映射（避免大改 auth store）：**

| Nest `user` | Admin `boUser` |
|-------------|----------------|
| `id` | `boUserId` |
| `username \|\| email` | `name` |
| `email` | `email` |
| `role === 'admin'` → `VITE_LOGIN_SUPER_NAME`（默认 `super admin`），否则 `user` | `accountType` |
| `'admin'` | `hierarchy`（取值受限，固定此项以兼容类型） |
| `status` | `status` |
| — | `privileges=[]` `boRoles=[]` |

### 4.2 列表查询

```text
JQSearch 提交 { keyword, status, role }
  → GET /admin/users?page=&pageSize=&keyword=&status=&role=
  → items + total → JQDataTable 分页
```

关键字：`email` **或** `username` 的 contains（大小写不敏感，Postgres `mode: insensitive`）。空条件忽略。

### 4.3 创建（Q-02 / Q-10）

```text
弹窗：email、password、username?、role?(默认 user)
  → POST /admin/users
  → 邮箱 toLowerCase；bcrypt(10)；status=active；emailVerifiedAt=now()
  → 不发验证码、不走 /auth/register
```

### 4.4 编辑资料（含 Should 改邮箱）

```text
弹窗回填：username、email、role（不回填密码）
  → PATCH /admin/users/:id
  → 唯一冲突 → 409 + EMAIL_TAKEN / USERNAME_TAKEN
```

状态与角色也可经 PATCH 提交；列表行上的「启用/禁用」走同一 PATCH（只带 `status`）。

### 4.5 启用 / 禁用 / 激活（Q-09）

允许的 `status` 目标值仅 `active` | `disabled`（不能写回 `pending_verification`）。

| 从 | 到 `active` | 到 `disabled` |
|----|-------------|---------------|
| pending_verification | 激活，写 `emailVerifiedAt=now()` | 允许 |
| active | 幂等 | 禁用，并**撤销该用户全部未过期 refresh** |
| disabled | 重新启用 | 幂等 |

禁用后：JWT strategy 已拒绝非 `active`，现有 access 在过期前仍可能短窗口可用（TTL 默认 1h）。**Must 接受该窗口**；缓解：撤 refresh，禁止续期。不在本期做 access 黑名单。

### 4.6 重置密码（Q-06）

```text
独立弹窗：新密码（8–72，与 RegisterDto 一致）
  → POST /admin/users/:id/reset-password
  → bcrypt 更新；revoke 该用户全部 refresh
```

允许管理员重置**自己的**密码（Q-03 只禁禁用/降级自己）。

### 4.7 自我保护与最后 admin（Q-03）

在 **Service 写路径**统一校验（PATCH status/role、未来若误加删除也挡住）：

1. `targetId === currentUser.userId` 且本次将导致 `status=disabled` 或 `role=user` → `CANNOT_MODIFY_SELF` **403**
2. 目标当前为 `role=admin` 且 `status=active`，本次将使其不再是「active admin」，且库中 `role=admin AND status=active` 计数为 1 → `LAST_ADMIN` **403**

创建另一个 admin、把已禁用 admin 再启用，均允许。

### 4.8 非 admin 访问

```text
无/坏 JWT → 401
JWT 有效但 role≠admin → 403（列表不得返回 items）
```

## 5. 数据模型

沿用现表，**无 migration**。管理端对外 DTO（不含 `passwordHash`、不含 `plan`）：

```text
AdminUser {
  id, email, username, role, status, emailVerifiedAt, createdAt, updatedAt
}
```

| 字段 | 列表 | 创建 | PATCH |
|------|------|------|--------|
| email | 展示/筛 | 必填 | Should，唯一 |
| username | 展示/筛 | 可选 | 可选，唯一；空串视为 `null` |
| password | 无 | 必填 8–72 | 不在 PATCH；走 reset 接口 |
| role | 展示/筛 | 默认 `user` | 可选 |
| status | 展示/筛 | 固定 `active` | 仅 `active`/`disabled` |

## 6. 接口设计

前缀：**无全局 prefix**（与现网一致，直连 `http://localhost:3000`）。全部需 `Authorization: Bearer <accessToken>`，除登录/刷新外。

### 6.1 管理端（新）

| 方法 | 路径 | 说明 | 用例 |
|------|------|------|------|
| GET | `/admin/users` | 分页列表 | UC-01/02 |
| POST | `/admin/users` | 创建 | UC-03 |
| PATCH | `/admin/users/:id` | 改资料/角色/状态 | UC-04/05/06/08/14 |
| POST | `/admin/users/:id/reset-password` | 重置密码 | UC-07 |

不提供 GET 详情（编辑用列表行数据）；不提供 DELETE（Q-04）。

**Query `GET /admin/users`**

| 参数 | 类型 | 默认 | 规则 |
|------|------|------|------|
| page | number | 1 | ≥1 |
| pageSize | number | 20 | 1–100 |
| keyword | string | — | email/username contains |
| status | UserStatus | — | 精确 |
| role | UserRole | — | 精确 |

**成功体**

```json
{
  "items": [ { "id": "...", "email": "...", "username": null, "role": "user", "status": "active", "emailVerifiedAt": "...", "createdAt": "...", "updatedAt": "..." } ],
  "total": 100,
  "page": 1,
  "pageSize": 20
}
```

创建 / PATCH / 重置密码：返回更新后的单个 `AdminUser`（重置密码同样不回密码）。

**请求体**

`POST /admin/users`：`{ email, password, username?, role? }`  
`PATCH /admin/users/:id`：上述字段均可选，外加 `status?: 'active'|'disabled'`  
`POST .../reset-password`：`{ password }`

### 6.2 后台认证（与 Electron 隔离）

| 方法 | 路径 | Admin 用途 |
|------|------|------------|
| POST | `/admin/auth/login` | 后台登录（仅 admin+active） |
| POST | `/admin/auth/refresh` | 续期 |
| GET | `/admin/auth/me` | 启动时拉用户 |
| POST | `/admin/auth/logout` | 登出时带 refreshToken（只作废后台 refresh） |

桌面端仍用 `/auth/*`。Electron JWT 调 `/admin/*` → 401；后台 JWT 调 `/auth/me`、`/tasks` → 401。

### 6.3 错误码（JSON 与现 `AuthException` 同形：`{ code, message, requestId? }`）

| code | HTTP | 场景 |
|------|------|------|
| `EMAIL_TAKEN` | 409 | 邮箱占用 |
| `USERNAME_TAKEN` | 409 | 用户名占用 |
| `USER_NOT_FOUND` | 404 | id 不存在 |
| `CANNOT_MODIFY_SELF` | 403 | 禁/降级自己 |
| `LAST_ADMIN` | 403 | 去掉最后一个 active admin |
| `INVALID_STATUS` | 400 | 试图写成 `pending_verification` 等 |
| （校验） | 400 | class-validator 默认 message 数组 |
| （无角色） | 403 | 后台登录非 admin；RolesGuard |
| （无令牌 / 桌面端 JWT） | 401 | JwtAdminAuthGuard |

Admin 用 `message`（或 `code` 映射 i18n）展示，**禁止** `console.log`。

### 6.4 Admin Nest 客户端（Q-07 定稿）

**不选：** 让 Nest 包 `{ code:0, data }`（污染多客户端）；**不选：** 改全局 `shared.ts`。

**选用：** `src/service/request/nest.ts`

| 钩子 | 行为 |
|------|------|
| `isBackendSuccess` | HTTP `status` 2xx（忽略 body.code） |
| `transform` | `response.data` 原样（无 `.data.data`） |
| `onRequest` | `Authorization` 用现有 `getAuthorization()` |
| HTTP 401 | 调 Nest `POST /admin/auth/refresh`；成功则更新 token 并重放；失败 `resetStore` |
| 其它 4xx/5xx | `$message` 展示 `message`；`error` 返回给调用方 |

开发代理：`.env` 增加 `VITE_NEST_BASE_URL=http://localhost:3000`。`VITE_HTTP_PROXY=Y` 时 nest 客户端 baseURL 用 `/proxy-nest`，在 `createViteProxy` **增量**一条 target（改 `build/config/proxy.ts` 或 env `VITE_OTHER_SERVICE_BASE_URL`）。生产：`VITE_NEST_BASE_URL` 指向同源反代或 Nest 公网地址。

登录/用户 API 均走 nest 客户端，**不再**请求 `/public/bo/auth/login`、`/gate/bo/user/me`。

## 7. 技术选型与备选

| 决策 | 选择 | 备选 | 理由 |
|------|------|------|------|
| 管理路由前缀 | `/admin/users` | `/bo/users`、挂在 `/auth` | 与终端用户 auth 分离；不沿用 O2O |
| 改角色生效 | DB 读 role，JWT 不含 role | role 写入 JWT | 避免改角色要等 access 过期 |
| 创建激活 | 直接 active | 仍发验证码 | Q-02；后台已人工确认 |
| 协议适配 | Admin 专用 nest 客户端 | Nest 包一层 code | 遵守 shared.ts 禁改；Electron 仍用裸 JSON |
| 状态接口 | 并入 PATCH | 单独 `/disable` | 表单与行内操作共用 |
| 种子 | Prisma seed + env | 纯文档 SQL | 本地联调可重复执行（UC-13） |
| 页面层级 | `manage/user` | `user/index` 单层 | 对齐已有 `page.manage.user` 文案骨架 |
| 列表 mock | Could，`AUTH_MOCK=Y` | 无 mock | 正式验收必须 Nest |

## 8. 风险与对策

| 风险 | 等级 | 对策 | 追溯 |
|------|------|------|------|
| 全局请求层把 Nest 200 当失败（无 `code=0`） | 高 | §6.4 独立客户端 | NFR-03 Q-07 |
| JwtStrategy 无 role → 守卫无法判定 | 高 | §3.1 扩 `AuthUser` | UC-10 |
| 禁用后 access 在 TTL 内仍可用 | 中 | 撤 refresh；文档接受短窗口 | UC-05 AC-04 |
| 误操作唯一 admin | 高 | §4.7 服务端硬约束 | UC-09 AC-07 |
| 前端菜单 stub 造成假权限 | 中 | 产品接受；验收看接口 | Q-08 AC-10 |
| CORS 挡联调 | 中 | Vite 代理 + Nest `enableCors` | NFR-04 |
| 登录仍 mock 导致无 JWT | 高 | 验收清单要求 `VITE_AUTH_MOCK=N` | Q-01 |
| `useDialogForm` 内含 `console.error` | 低 | 页面优先直连 `JQDialogForm` 的 `onSubmit`，不扩该 hook 的日志 | NFR-06 |
| e2e 内存 Prisma mock 需同步 role/status 新路径 | 中 | 扩展 `app.e2e-spec` 或新增 admin-users e2e | AC-08 |
