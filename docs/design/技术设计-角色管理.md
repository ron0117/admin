## 1. 目标与约束

| 项 | 内容 |
|----|------|
| 目标 | Electron 生图菜单权限：Nest 存菜单/角色/绑定；后台配置；桌面按并集裁剪导航 |
| 技术基座 | Admin：JQ* + `nest.ts`；Nest：Prisma；Electron：现有 `/auth/*` 会话 + `GENERATE_NAV` |
| 约束 | 不改 `admin/.../request/shared.ts`；不恢复 privilege 树；不物理删角色/菜单；`User.role` 枚举暂留不用 |
| 非目标 | 后台自身 RBAC；菜单管理 CRUD；按钮/数据权限；抖店/工作台/设置裁剪；改完立刻踢 access |

### 1.1 可行性（Go）

| 维度 | 结论 | 说明 |
|------|------|------|
| 数据 | Go | 新表 `Menu` / `Role` / `RoleMenu` / `UserRole`；`User` 加关系 |
| 鉴权 | Go | 管理接口 `JwtAdminAuthGuard`；桌面 `JwtAuthGuard` + `me`/`login`/`refresh` 带 `menus` |
| 协议 | Go | Admin `nest.ts`；Electron 扩 `AuthStatus.menus` |
| 页面 | Go | 两层 `manage/role`；配置用宽对话框 + `ElTree`（已全局注册） |
| 桌面 | Go | 路径↔code 对照表；守卫回工作台 |

**门禁：Go。** 须 migrate + 菜单 seed；Electron 须能拉到 `menus`。

## 2. 总体架构

```text
Admin
  ├─ views/manage/role     ──► /admin/roles*  + PUT menus
  ├─ views/manage/user     ──► /admin/users*  增加 roleIds / roles
  └─ GET /admin/menus/tree 只读种子树

Nest
  ├─ MenusModule（只读树）     JwtAdminAuthGuard
  ├─ RolesModule（新）         /admin/roles*
  ├─ AdminUsersModule          读写 UserRole
  ├─ AuthModule                login/refresh/me 附加 menus[]
  └─ seed                      upsert 生图 Menu 树

Electron
  ├─ 登录 / 启动 me            缓存 menus[]
  ├─ AppLayout 顶栏            menus 含 generate 或其子孙 → 显示「生图」
  ├─ GenerateNav               按叶子 code 过滤
  └─ router guard              /generate/** 无对应叶子 → /workbench/main/home
```

菜单码**不进 JWT**，每次签发会话或 `me` 时查库展开，避免 token 膨胀与过期权限。

### 3.1 NestJS

## 4. 关键流程

### 4.1 保存角色菜单（勾父=只存父）

```text
PUT /admin/roles/:id/menus  { codes: string[] }
  → 校验 code 均存在
  → 规范化：若 codes 含某节点，去掉其全部子孙（父已覆盖）
  → 事务：删旧 RoleMenu，按规范化 codes 插入
```

树回显：角色已存父码 → 该节点及子孙在 UI 上视为勾选；半选：仅部分子孙在库中。

### 4.2 展开有效菜单（me / 登录）

```text
resolveMenus(userId):
  取 UserRole 且 Role.status=active 的 RoleMenu → 得到 assigned Codes
  加载全表 Menu 建父子图
  effective = ∅
  对每个 assigned：
    加入自身
    加入全部子孙          // Q-R2 勾父后新子菜单自动有
    加入全部祖先          // 只勾叶子时顶栏仍有「生图」
  返回 sorted unique codes
```

禁用角色：不进入 assigned（绑定行保留，UC-15）。

### 4.3 桌面裁剪

```text
hasGenerate = menus 含 "generate"   // 展开后：有任意生图权限必含父码
叶子可见 = menus 含该 path 对应 code
进入 /generate/xxx：
  映射 path → code（最长前缀）
  无 code 或 menus 不含 → replace /workbench/main/home
无 hasGenerate：顶栏不渲染生图；已在生图路由则同样回工作台
```

### 4.4 用户绑角色

```text
POST/PATCH /admin/users  { ..., roleIds?: uuid[] }
  → 只允许 Role.status=active（禁用角色 id → 400）
  → 事务替换 UserRole
列表 GET 带 roles: [{ id, name }]（仅 active，按 name）
```

## 5. 数据模型

```prisma
enum RoleStatus {
  active
  disabled
}

model Menu {
  id        String     @id @default(uuid()) @db.Uuid
  code      String     @unique
  name      String
  parentId  String?    @db.Uuid
  parent    Menu?      @relation("MenuTree", fields: [parentId], references: [id], onDelete: Restrict)
  children  Menu[]     @relation("MenuTree")
  sort      Int        @default(0)
  createdAt DateTime   @default(now())
  roleMenus RoleMenu[]
}

model Role {
  id        String     @id @default(uuid()) @db.Uuid
  name      String     @unique
  remark    String?
  status    RoleStatus @default(active)
  createdAt DateTime   @default(now())
  updatedAt DateTime   @updatedAt
  roleMenus RoleMenu[]
  userRoles UserRole[]
}

model RoleMenu {
  roleId String @db.Uuid
  menuId String @db.Uuid
  role   Role   @relation(fields: [roleId], references: [id], onDelete: Cascade)
  menu   Menu   @relation(fields: [menuId], references: [id], onDelete: Restrict)

  @@id([roleId, menuId])
  @@index([menuId])
}

model UserRole {
  userId String @db.Uuid
  roleId String @db.Uuid
  user   User   @relation(fields: [userId], references: [id], onDelete: Cascade)
  role   Role   @relation(fields: [roleId], references: [id], onDelete: Restrict)

  @@id([userId, roleId])
  @@index([roleId])
}
```

`User` 增加 `userRoles UserRole[]`。菜单无 status（种子固定）。角色禁用不级联删 `UserRole`。

**种子（code 锁定，与 Electron path 对齐）：**

| code | name | parent | sort | Electron path |
|------|------|--------|------|----------------|
| `generate` | 生图 | — | 0 | 顶栏 section |
| `generate.create.inspire` | 灵感创作 | generate | 10 | `/generate/create/inspire` |
| `generate.create.fission` | 去同质化裂变 | generate | 20 | `/generate/create/fission` |
| `generate.create.scene-renew` | 原景出新 | generate | 30 | `/generate/create/scene-renew` |
| `generate.create.free` | 自由创作 | generate | 40 | `/generate/create/free` |
| `generate.create.live` | live图生成 | generate | 50 | `/generate/create/live` |
| `generate.create.copywrite` | 文案仿写 | generate | 60 | `/generate/create/copywrite` |
| `generate.manage.history` | 历史任务 | generate | 70 | `/generate/manage/history` |
| `generate.manage.disk-cleanup` | 磁盘清理 | generate | 80 | `/generate/manage/disk-cleanup` |

后续新子菜单：seed upsert 新行即可；已勾父 `generate` 的角色无需重配。

公开角色字段：`id, name, remark, status, createdAt, updatedAt`（可另附 `menuCodes` 仅在配置 GET）。

## 6. 接口

管理端：`JwtAdminAuthGuard` + Bearer `JWT-Admin`。桌面：`JwtAuthGuard` + `JWT`。

### 6.1 菜单树

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/admin/menus/tree` | `{ items: MenuNode[] }`，`MenuNode: { id, code, name, sort, children }` |

### 6.2 角色

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/admin/roles` | `page,pageSize,keyword?,status?` → `{ items, total, page, pageSize }` |
| POST | `/admin/roles` | `{ name, remark? }` → active |
| PATCH | `/admin/roles/:id` | `{ name?, remark?, status?: active\|disabled }` |
| GET | `/admin/roles/:id` | 含 `menuCodes: string[]`（库内规范化后的码，未展开子孙） |
| PUT | `/admin/roles/:id/menus` | `{ codes: string[] }` 全量覆盖 |

错误：`ROLE_NAME_TAKEN` 409、`USER_NOT_FOUND` 404（文案「角色不存在」）、非法 code `INVALID_STATUS` 或新码 `MENU_NOT_FOUND` 400。无物理 DELETE。

### 6.3 用户

| 项 | 现状 | 目标 |
|----|------|------|
| GET 列表项 | 无角色 | `roles: { id, name }[]`（active） |
| query | keyword/status | 增加可选 `roleId` |
| POST/PATCH | 无 | 可选 `roleIds: string[]`；省略 PATCH 则不改绑定；POST 默认 `[]` |

### 6.4 桌面会话

`POST /auth/login`、`POST /auth/refresh`、`GET /auth/me` 在现有 `{ user, ... }` 上增加：

```json
{ "user": { "...现有 PublicUser" }, "menus": ["generate", "generate.create.inspire", "..."] }
```

`me` 现为 `{ user }`，改为 `{ user, menus }`。login/refresh 已有 token 字段，并列 `menus`。Electron 忽略未知字段即可前向兼容旧客户端；新客户端必须读 `menus`（缺省当 `[]`）。

不把业务 `roles[]` 暴露给桌面（最小权限面）；桌面只需要 `menus`。

## 7. 技术选型与备选

| 点 | 选用 | 不选 |
|----|------|------|
| 菜单来源 | 种子表 | 后台菜单 CRUD；纯前端写死无库 |
| 父勾语义 | 库中只存父码；读取时展开子孙 | 存全部叶子（新子菜单要重勾） |
| 配置 UI | 列表行 → 对话框树 | 独立第三层路由；PageMenu Tab（可后期改，非必须） |
| 权限下发 | 会话 JSON `menus[]` | JWT claims；单独 `/auth/menus` |
| 桌面缓存 | 内存 + 每次启动 me | 只信登录瞬间、永不 me |

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| path 与 code 漂移 | 对照表单测；seed 与 `GENERATE_NAV` 同 PR |
| `me` 形状变化致旧 Electron 崩 | 只**增加**字段；旧客户端不读 `menus` 则仍全开——**本期新 Electron 必须读**，缺省 `[]` 才会藏生图 |
| 旧桌面未升级仍显示全生图 | 可接受一版窗口；README 写明需升桌面端 |
| e2e mock 缺新表 | 先扩内存 Map 再写用例 |
| 勾全叶子未折叠成父 | 保存时规范化；否则 Q-R2 新子菜单不会自动有 |
| `Role` 模型名与枚举 `UserRole` 混淆 | API/UI 一律 `roles` / `roleIds`，不用枚举 |
