## 1. 目标与约束

| 项 | 内容 |
|----|------|
| 目标 | 运营批量生成卡密、分页列表（含明文）、筛选、导出 CSV；兑换记录可对账 |
| 基座 | JQ* + `nestRequest`；用户远程搜索复用 `GET /admin/users` |
| 约束 | 卡密仅经 HTTPS + Admin JWT；不在浏览器 localStorage 缓存导出文件 |
| 非目标 | 作废卡密 UI；wzyp 对接；Ping++ 档位继续维护 |

### 1.1 可行性（Go）

| 维度 | 结论 |
|------|------|
| Nest API | Go（扩展现有 `recharge` module） |
| 表格页 | Go（对齐 `points/recharge/records`） |
| 菜单 | Go（elegant-router + i18n） |
| 权限 | Go（与积分模块同套菜单权限） |

**门禁：Go。** 依赖 Nest migrate + 路由/i18n 注册。

## 4. 卡密管理页

### 4.1 布局

- `JQCustomPage` + 顶栏操作区 + `JQDataTable`（**分页**）。
- 顶栏：**生成卡密**（打开 `JQDialogForm`）、**导出**（按当前筛选条件下载 CSV，Should）。

### 4.2 生成弹窗

| 字段 | 控件 | 校验 |
|------|------|------|
| 数量 `count` | `inputNumber` | 必填；1～500（与 Nest `RECHARGE_CARD_BATCH_MAX` 一致） |
| 到账积分 `points` | `inputNumber` | 必填；整数 ≥ 1 |
| 批次备注 `batchNote` | `input` | 可选；≤ 200 字 |

提交：`POST /admin/recharge-cards/generate` → 关闭弹窗 → 刷新列表 → `ElMessage.success` 提示生成条数。

### 4.3 列表列

| 列 | 字段 | 说明 |
|----|------|------|
| 卡密 | `code` | 明文；列宽偏大；可复制（`el-text` + 复制按钮 optional） |
| 积分 | `points` | |
| 状态 | `status` | `unused` →「未兑换」；`redeemed` →「已兑换」 |
| 批次备注 | `batchNote` | 空则 `—` |
| 生成时间 | `createdAt` | formatTime |
| 兑换时间 | `redeemedAt` | 未兑换 `—` |
| 兑换账号 | `redeemedUserEmail` | join 用户；未兑换 `—` |

### 4.4 筛选（表格上方 search）

| 项 | 组件 |
|----|------|
| 状态 | select：全部 / 未兑换 / 已兑换 |
| 生成时间 | `datetimerange` → `createdFrom` / `createdTo` |
| 积分 | `inputNumber`（精确匹配，optional） |
| 卡密 | `input` 模糊 `codeKeyword`（optional） |
| 兑换账号 | 仅当状态含已兑换时展示：`el-select` remote → `fetchAdminUserList`，传 `redeemedUserId` |

查询：`GET /admin/recharge-cards?page&pageSize&…`。

### 4.5 导出

- 按钮「导出 CSV」：带当前筛选 query，请求 `GET /admin/recharge-cards/export?…`。
- 响应 `Content-Disposition: attachment`；前端 `blob` 下载。
- 列：卡密、积分、状态、批次备注、生成时间、兑换时间、兑换账号。

## 5. 兑换记录（MVP）

**不单独做第三页**（梳理版允许与列表复用）：

- 卡密管理页筛选 **状态=已兑换** + 兑换账号/时间即「兑换记录」视图。
- **Should**：`points/records` 继续支持 `type=recharge`，remark 含卡密 id/后缀便于对账。

若后续要独立菜单，可复用同一 API `status=redeemed` 的只读页（Could）。

## 6. API 封装（`src/service/api/recharge.ts`）

```ts
// 类型草案（与 Nest Swagger 对齐后微调）
type RechargeCardStatus = 'unused' | 'redeemed';

type RechargeCard = {
  id: string;
  code: string;
  points: number;
  status: RechargeCardStatus;
  batchNote: string | null;
  createdAt: string;
  redeemedAt: string | null;
  redeemedUserId: string | null;
  redeemedUserEmail: string | null;
  redeemedUserUsername: string | null;
};

type GenerateRechargeCardsInput = {
  count: number;
  points: number;
  batchNote?: string;
};

fetchGenerateRechargeCards(body: GenerateRechargeCardsInput): Promise<{ created: number }>;
fetchRechargeCards(query: Pagination & filters): Promise<Paginated<RechargeCard>>;
fetchExportRechargeCards(query: filters): Promise<Blob>; // 或 window.open + token 方案见 nestRequest 惯例
```

## 7. 关键流程

```text
运营打开卡密管理 → 生成 N 张（积分 P）→ 列表未兑换
  → 导出 CSV → 店铺上架（系统外）
用户桌面兑换 → Nest 已兑换
  → Admin 筛选已兑换 / 积分流水 recharge
```

## 9. 风险

| 风险 | 对策 |
|------|------|
| 明文泄露 | Admin 权限；运营规范；后续可改脱敏 |
| 一次生成过多 | 前后端双限 500 |
| 导出超大 CSV | 限制单次导出 max 10000 行（Nest 设计） |
