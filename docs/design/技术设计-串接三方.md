# 技术设计 · 串接三方（Ping++ 充值）

## 1. 目标与约束

| 项 | 内容 |
|----|------|
| 目标 | Ping++ 充值全链路：运营配档位、用户桌面充值、后台查订单、Nest 入账写 `recharge` 流水 |
| 基座 | Admin：JQ* + `nestRequest`；Nest：Prisma + 双 JWT；Electron：Main HTTP + BrowserWindow |
| 约束 | 不把 Ping++ sk 下发客户端；Webhook raw body 验签；管理 DTO 不进 `packages/contracts` |
| 非目标 | 限购、导出、退款 UI、Live 多渠道一次全开、用户端充值历史页 |

### 1.1 可行性（Go）

| 维度 | 结论 | 说明 |
|------|------|------|
| 积分底座 | Go | `User.points`、`PointLedger` 已存在；扩展 enum + 新表 |
| Ping++ | Go | 官方 `pingpp` Node SDK + Webhook 文档成熟 |
| Admin 列表 | Go | 复刻 `points/records`；用户筛选用现有 `GET /admin/users?keyword=` |
| Electron WebView | Go | 已有 `BrowserPublisher` 的 BrowserWindow 模式可借鉴（独立 partition） |
| 公网 Webhook | ⚠️ | 部署需 HTTPS；dev 用隧道 |

**门禁：Go。** 阻塞项：Ping++ Test 商户参数、Webhook 可达、migrate。

## 2. 总体架构

```text
Admin
  ├─ views/points/recharge/packages   ──► CRUD /admin/recharge-packages
  ├─ views/points/recharge/records      ──► GET /admin/recharge-orders
  └─ (可选) points/records              ──► 增加 type=recharge 筛选项

Nest nest-api
  ├─ RechargeModule
  │    Admin：档位、订单分页
  │    桌面：GET packages、POST/GET orders
  │    公开：POST /webhooks/pingpp
  │    Cron：关闭超时 pending 订单
  └─ PointsModule（已有）              recharge 入账复用事务模式

Electron
  ├─ section account + pages/account/main/home
  ├─ UserStatus → 账号路由
  ├─ IPC recharge:* → Main → Nest
  └─ RechargePayWindow（BrowserWindow 加载 payUrl）
```

## 3. Admin 模块

### 3.1 路由（elegant-router）

在现有 `points` 父路由下增加两层子路由（与 `settings` / `records` 同级）：

| name | path | 组件 | 菜单文案（zh-cn） |
|------|------|------|-------------------|
| `points_recharge_packages` | `/points/recharge/packages` | `view.points_recharge_packages` | 充值管理 |
| `points_recharge_records` | `/points/recharge/records` | `view.points_recharge_records` | 充值记录 |

侧栏父级 `route.points` 标题改为 **积分管理**（i18n 调整，不改路由 name）。

### 3.2 充值管理页

- 布局：`JQCustomPage` + `JQDataTable`（可分页或全量档位，预计条数少，**不分页亦可**）。
- 列：排序、支付金额（元）、基础积分、赠送积分、合计积分、上架状态、更新时间、操作（编辑/上架/下架）。
- 新建/编辑：`JQDialogForm`；金额 `inputNumber` 最小 0.01 或 1 元（产品定 1 元整数 Must）；积分非负整数。
- API：`src/service/api/recharge.ts`（或并入 `points.ts` 子文件），仅 `@/service/api` 出口。

### 3.3 充值记录页

- 对齐 `views/points/records/index.vue`。
- 搜索项：
  - **账号**：`el-select` `remote` + `remote-method` → `fetchAdminUserList({ keyword, pageSize: 20 })`，选中存 `userId`。
  - **时间**：`datetimerange` → `from` / `to` ISO。
  - **状态**：pending / paid / failed / closed（可选 clearable）。
- 表格列：账号（email/username）、充值额度、手续费、实际到账、到账积分、状态、创建时间、支付时间、订单号（可复制）。
- 金额展示：`cents / 100` 固定两位小数。

### 3.4 积分流水（Should）

`points/records` 的 `typeOptions` 增加 `recharge` 文案「充值」；依赖 Nest `GET /admin/point-ledgers` 支持该 type（见 Nest 设计）。

## 4. 关键流程（Admin 视角）

```text
运营维护档位 → 桌面用户充值 → Webhook 入账
  → 充值记录页可见订单
  → （Should）积分流水可见 recharge 行
```

## 5. API 类型（Admin 前端草案）

```ts
type RechargePackage = {
  id: string;
  amountCents: number;
  basePoints: number;
  bonusPoints: number;
  onShelf: boolean;
  sort: number;
  updatedAt: string;
};

type RechargeOrder = {
  id: string;
  userId: string;
  userEmail: string;
  userUsername: string | null;
  orderNo: string;
  amountCents: number;
  feeCents: number;
  netCents: number;
  pointsCredited: number;
  status: 'pending' | 'paid' | 'failed' | 'closed';
  createdAt: string;
  paidAt: string | null;
};
```
