> 已锁定：Q-01 单价 0 免费仍记账；Q-02 TTL 20 分钟自动退还；Q-03 取消=退还；Q-04 调减不得超余额；Q-05 无用户端流水；Q-06 无支付充值；Q-07 文案按条数；Q-08 自由创作按钮「生成图片」

## 1. 目标与约束

| 项 | 内容 |
|----|------|
| 目标 | 后台配 6 个创作功能积分；桌面生成展示总价并真实预扣；运营可调账、查流水 |
| 技术基座 | Admin：JQ* + 现有 `nest.ts`；Nest：Prisma + JwtAdmin / Jwt 桌面；Electron：现有 `/auth/*` + 创作 `requestId` |
| 约束 | 不改 `admin/.../request/shared.ts`；不恢复 privilege 树；积分不进 JWT；不把管理 DTO 塞进 `packages/contracts` |
| 非目标 | 支付充值、套餐/`plan`、邀请、导出、用户端流水、历史/清理扣费 |

### 1.1 可行性（Go）

| 维度 | 结论 | 说明 |
|------|------|------|
| 数据 | Go | `User.points` + `PointFeature` / `Spec` / `Ledger`；须 migrate + seed |
| 鉴权 | Go | 管理 `JwtAdminAuthGuard`；桌面 `JwtAuthGuard`；两套 JWT 已隔离 |
| 协议 | Go | Admin 走 `nest.ts`；Electron Main 扩 `auth-api-client` |
| 页面 | Go | 两层 `points/settings`、`points/records`；弹窗 `JQDialogForm` |
| 桌面 | Go | 现有生成已带 `requestId`；CTA 拼文案；IPC 新通道须写 `docs/IPC.md` |
| TTL | Go | nest-api 内 `@nestjs/schedule` 扫过期 pending，不走 AI/Browser 队列 |

**门禁：Go。** 阻塞项为 migrate/seed 与桌面 hold 必须发生在生成 IPC 之前。

## 2. 总体架构

```text
Admin
  ├─ views/points/settings   ──► GET/PATCH /admin/point-features
  ├─ views/points/records    ──► GET /admin/point-ledgers
  └─ views/user/list         ──► GET /admin/users(+points)
                                 POST /admin/users/:id/points

Nest nest-api
  ├─ PointsModule
  │    管理：功能设置、流水
  │    桌面：GET /point-features；POST /points/hold|commit|refund
  │    TTL：每 60s 退还过期 pending
  ├─ AuthModule               user.points 并入 me/login/refresh
  └─ AdminUsersModule         列表带 points；调账委托 PointsService

Electron
  ├─ 登录 / me                缓存 points + 功能设置
  ├─ 顶栏 UserStatus          展示 session.points
  ├─ 创作页 CTA               单价 × 数量
  └─ 生成前                   hold → 现有 IPC 生成 → commit / refund
```

菜单码、积分数**不进 JWT**。每次 hold 读库单价并写入流水快照。

## 3. 模块职责

### 3.1 NestJS（摘要）

| 模块 | 路径 | 职责 |
|------|------|------|
| Schema / Seed | `prisma/` | `User.points`；功能/规格/流水；6 功能幂等种子 |
| Points | `apps/nest-api/src/points/` | 功能设置、hold/commit/refund、调账、流水、TTL |
| Auth | `auth.service` | `PUBLIC_USER_SELECT` + `toPublicUser` 增加 `points` |
| AdminUsers | `admin-users/` | 出参 `points`；`POST :id/points` |
| Env | `.env.example` | `POINTS_HOLD_TTL_SEC` 默认 1200 |

细节见 Nest 技术设计（事务、部分唯一索引、错误码）。

### 3.2 Admin

| 模块 | 路径 | 职责 |
|------|------|------|
| 功能设置 | `views/points/settings/index.vue` | `JQCustomPage` + `JQDataTable`（6 行不分页）+ 操作「修改」+ `JQDialogForm` |
| 积分流水 | `views/points/records/index.vue` | `JQSearch` + `JQDataTable` 分页 |
| 用户列表 | `views/user/list/index.vue` | 列「积分」；「调整积分」弹窗 |
| API | `service/api/points.ts` + 用户 API 补 `points` | 只从 `@/service/api` 引入 |
| 路由 | elegant `points` / `points_settings` / `points_records` | 与 `user` 并列两层 |
| i18n | `route.points*`、`page.points.*` | 至少 `zh-cn`；三语与现网对齐 |

弹窗字段对齐梳理版 §3.4 A：live 三个 `inputNumber`，其余一个单价 + 备注。页脚可静态提示：「改价对正在进行的生成不生效」。

### 3.3 Electron

| 模块 | 路径 | 职责 |
|------|------|------|
| IPC | `shared/ipc.ts` + preload + `docs/IPC.md` | `points:get-features` / `hold` / `commit` / `refund` |
| HTTP | `main/auth/auth-api-client.ts` 或 `points-api-client.ts` | 调 Nest 桌面接口，带 accessToken |
| 会话 | `shared/auth.ts`、`session.ts` | `AuthStatus.points`；登录/`me` 写入顶栏，权威在服务端 |
| 配置缓存 | renderer composable `use-point-features.ts` | 启动/进创作拉取；计算 `unit × qty` |
| CTA | 6 个创作页 | 拼 `{动作} · {n} 积分`；不足可点但 hold 失败 toast 拦截 |
| 生成包装 | 各页现有 generate 函数最外层 | 先 hold，成功再 IPC；失败/取消 refund；成功 commit |

历史 / 磁盘清理不调用 hold。

**CTA 动作文案（保持现状）：**

| 场景 | 前缀 | specKey | 数量 |
|------|------|---------|------|
| 灵感 | 开始创作 | `default` | 张数，缺省 1 |
| 裂变 | 一键裂变 | `default` | 裂变张数 |
| 出新 | 一键出新 | `default` | 张数，缺省 1 |
| 自由 | 生成图片 | `default` | 张数，缺省 1 |
| live | 生成 live 图 | `high`/`medium`/`good` | 张数 |
| 文案 | AI 生成仿写 | `default` | 生成条数 |

live 废弃本地 `LIVE_CLARITY_POINTS` 作为扣费来源，仅可作无配置时的 UI 兜底（与种子 0 冲突时：**以后台为准**，无行则 0）。

## 4. 关键流程

### 4.1 修改功能设置

```text
PATCH /admin/point-features/:menuCode
  { remark, specs: [{ specKey, unitPoints }] }
  → 校验 menuCode 属于 6 创作
  → specs 必须与该功能种子 specKey 集合相等
  → 事务更新 remark + 各 unitPoints
Electron 下次 GET /point-features 才看到新价
```

### 4.2 生成扣费

```text
用户点击 CTA
  → renderer：requestId = 已有 uuid（沿用本次生成）
  → IPC points:hold { requestId, menuCode, specKey, quantity }
  → Nest 条件扣余额 + 记 consume pending
  → 409 POINTS_INSUFFICIENT → toast「积分不足，需要 x，当前 y」；不调生成 IPC
  → 生成 IPC 成功 → points:commit
  → 生成失败 / 用户取消 → points:refund
  → hold 成功但 IPC 抛错：必须 refund（finally）
同 requestId 重试 hold：Nest 返回原笔，不二次扣
用户再点一次：新 requestId → 新一笔
```

### 4.3 调账

```text
POST /admin/users/:id/points { direction, amount, remark }
  → decrease 且 amount > points → 409
  → 事务改余额 + ledger admin_* completed
```

### 4.4 TTL

pending 且 `expiresAt < now` → 与 `refund` 同语义（nest-api 定时任务）。桌面若事后再 commit → `POINTS_HOLD_NOT_FOUND` 或已退还错误，生成结果若已出图：**不补扣**（接受极端窗口，见风险）。

## 5. 数据模型（产品视图）

| 实体 | 关键字段 |
|------|----------|
| User | `points Int >= 0` 默认 0 |
| PointFeature | `menuCode` 唯一、`name`、`remark` |
| PointFeatureSpec | `(featureId, specKey)` 唯一、`unitPoints` |
| PointLedger | `type/status/requestId/快照单价/quantity/amount/balanceAfter/expiresAt` |

消费 `requestId` 部分唯一。退还行通过 `refundOfId` 指向原 consume。

种子 6 功能与规格见梳理版 §3.1 / Nest 需求 §2。

## 6. 接口（契约摘要）

管理端 Bearer `JWT-Admin`；桌面 Bearer `JWT`。成功为裸 JSON；错误 `{ code, message }`。

| 方法 | Path | 调用方 |
|------|------|--------|
| GET | `/admin/point-features` | Admin 功能设置 |
| PATCH | `/admin/point-features/:menuCode` | Admin 修改弹窗 |
| GET | `/admin/point-ledgers` | Admin 流水 |
| POST | `/admin/users/:id/points` | Admin 调账 |
| GET | `/admin/users` | 增加 `points` |
| GET | `/auth/me` 等 | `user.points` |
| GET | `/point-features` | Electron CTA |
| POST | `/points/hold` | Electron 预扣 |
| POST | `/points/commit` | Electron 成功 |
| POST | `/points/refund` | Electron 失败/取消 |

错误码：`POINTS_INSUFFICIENT` 409、`POINTS_FEATURE_NOT_FOUND` 404、`POINTS_HOLD_NOT_FOUND` 404、`POINTS_ALREADY_COMMITTED` 409、`POINTS_ALREADY_REFUNDED` 409、`POINTS_ADJUST_EXCEEDS_BALANCE` 409、`POINTS_INVALID_SPECS` 400。

DTO 形状见 Nest 开发需求 §5–§6。

## 7. 技术选型

| 项 | 选型 | 备选 |
|----|------|------|
| 过期退还 | nest-api `@nestjs/schedule` 每 60s | `setInterval` 无新依赖 |
| 扣费并发 | `updateMany` `points >= cost` | 可串行化事务，成本更高 |
| 桌面调用 | Main 进程 HTTP + 新 IPC | Renderer 直连 Nest（禁止：token 在 Main） |
| Admin 列表 | 现有 JQ* | 不用 PageMenu（两层路由足够） |

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| hold 成功、commit 丢失 | TTL 退还；桌面 `finally` refund |
| TTL 退还后图已生成 | 记录 warn 日志；本期不补扣（Q-02 窗口） |
| 把「点两次」做成只扣一次 | 幂等键仅 `requestId` |
| live 本地 15/10/5 与后台不一致 | CTA/扣费只读 `/point-features` |
| 只改余额不记账 | 所有增减走 PointsService 事务 |
| 桌面旧包不 hold | 新包才扣费；文档说明须升级 |
