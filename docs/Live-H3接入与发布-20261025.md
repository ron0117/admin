# Live 视频切换 MiniMax-H3：改动与发布交接

日期：2026-10-25。状态：代码、自动化测试与本地客户端包准备完成；**线上由技术同事部署，尚未代为发布或配置生产密钥**。

## 给使用者看的变化

AI 动态使用「调研静态图片转 Live 图片」会话实测的 **Metaso 原生 MiniMax-H3**，请求 4 秒视频。界面默认 768P，保留原图比例、其他比例和自定义比例。非原图比例仍先裁切首帧，视频按照处理后首帧自适应。

| 功能 | 每张／每篇／每条积分 |
| --- | ---: |
| 图片生成 | 10 |
| 文案生成 | 3 |
| 本地镜头 Live | 1 |
| AI Live · 768P | 50 |
| AI Live · 1080P | 75 |
| AI Live · 2K | 85 |

本地镜头的八种动效继续在设备上运行。已有视频、历史结果、Live 导出和阿里云盘上传入口保留。导出 Live 仍使用现有的前 3 秒静音配对流程；下载视频保留供应商返回的完整片段。供应商返回时长可能略长于请求的 4 秒，本次不对原视频强制裁短，也不删除其中的生成标识。

断网后点击继续获取，会查询原任务。若创建请求的响应丢失且服务端未拿到上游任务编号，显示“提交结果待核对”，**不会自动再次提交收费生成**，需要管理员核对供应商记录。

## 发布顺序

1. 备份数据库、当前已发布 AI 配置版本和现用构建产物。服务端 `apps/nest-api` 下运行 `node scripts/point-prices-backup.cjs /安全目录/prices-before-h3.json`；数据库连接沿用部署环境的 `DATABASE_URL`。此文件只保存价格，不包含模型密钥。
2. 部署本分支服务端，按项目现有流程安装锁定依赖、`npm run prisma:generate`、`npm run prisma:deploy`、`npm run build`。本次新增迁移 `20261025110000_live_h3`：创建持久任务表并增加三档价格。前一积分迁移也要保留并按顺序执行。
3. 部署管理后台。先保留现有 Wan 服务，不要立即把仍在运行的旧 Wan 任务切断。旧任务最好先完成、取回视频，再切换 `live.generate`。
4. 更新桌面端至本分支构建的 `0.1.4`。旧客户端不识别新增协议，因此需要协调客户端与后台配置的切换顺序。
5. 在后台“模型配置”新增服务，按下表填写，保存草稿后，将“LIVE 创作 → 生成动态图片”绑定此服务并发布。动作提示词继续沿用原有支持识图的文本服务。
6. 在积分设置检查：本地 1、768P 50、1080P 75、2K 85。客户端重新同步后再验收。界面和预扣读取后台实际价格；后台价格缺失时不默认为免费。

### H3 服务配置

| 项目 | 值 |
| --- | --- |
| 调用方式 | `metaso-h3-video`（Metaso MiniMax-H3） |
| 接口基础地址 | `https://metaso.cn/api/minimax/v2` |
| 模型 | `MiniMax-H3`，注意大小写 |
| 密钥 | Metaso 自己的 API Key，通过后台密码框填写；不是原来 laozhang/Wan 的 Key |
| 超时 | 建议 1200 秒 |
| 支持图片识别 | 可关闭；本协议的首帧由视频请求直接携带 |
| 启用 | 是 |
| 绑定 | `live.generate` |

密钥由后台加密保存。H3 配置下发只含非敏感元数据，客户端即使收到误带的密钥也会丢弃。真正的请求由我方服务端发出。

部署依赖：`AI_CONFIG_ENCRYPTION_KEY` 保持稳定；我方服务端能访问 `metaso.cn` 与 `files.metaso.cn`；MinIO 已配置，`MINIO_PUBLIC_ENDPOINT` 必须能被桌面端访问。现有 Nginx 32MB 请求体限制足够；图片正文上限约 20MB。H3 走普通 `/api/`，不走 `/wan-proxy/`。

## 请求对照（给技术与 AI 接手者）

客户端向自己的服务器发送：

```http
POST /api/ai/live/h3/jobs
Authorization: Bearer <用户的平台 JWT>
Content-Type: application/json
```

```json
{
  "requestId": "本次积分预扣使用的请求编号",
  "resolution": "768p",
  "prompt": "保留商品和人物，仅做轻微自然动作……",
  "image": "data:image/png;base64,<图片内容>"
}
```

`resolution` 可选 `768p`、`1080p`、`2k`；同一预扣记录的规格必须匹配。服务端拒绝用 768P 的预扣发起 2K 请求。金额始终取后台积分规则，客户端不传可随意修改的价格。

服务端向 Metaso 发出原生请求：

```http
POST https://metaso.cn/api/minimax/v2/video_generation
Authorization: Bearer <仅服务端持有的 Metaso Key>
Content-Type: application/json
```

```json
{
  "model": "MiniMax-H3",
  "content": [
    { "type": "text", "text": "保留商品和人物，仅做轻微自然动作……" },
    { "type": "image_url", "image_url": { "url": "data:image/png;base64,<图片内容>" }, "role": "first_frame" }
  ],
  "resolution": "768P",
  "duration": 4,
  "ratio": "adaptive",
  "fast_mode": false,
  "context_ir_enabled": false
}
```

另两档分别传 `1080P`、`2K`。不再使用 Wan 的 720P、5 秒、`input.media` 或 `/v1/tasks/` 格式。

上游创建返回字符串 `task_id`。查询为 `GET /query/video_generation/{task_id}`；成功读 `task.status === 'succeeded'` 与 `task.content.url`。编号可能超过 JavaScript 安全整数范围，**全程保持字符串**。数值型编号将进入待核对，禁止精度丢失后继续查询错误任务。

客户端查询我方 `GET /api/ai/live/h3/jobs/{requestId}`。服务端持久保存用户、请求摘要、配置版本、服务 ID、上游编号、所选清晰度和结果存储位置。客户端可恢复的编号是 `h3_<requestId>`，区别于旧 Wan 编号。

成功视频下载到我方 MinIO，客户端领取短时签名地址再存入本机素材库。供应商临时链接不作为唯一历史存储。供应商/CDN 和 MinIO 下载请求不带模型密钥或平台 JWT；上游结果只接受 `https://files.metaso.cn`，不跟随重定向，文件上限 128MB，并检查 MP4 容器标记。

## 失败恢复与运维边界

- 同一用户、同一请求编号只能创建一个任务，重复 POST 返回已有记录；同编号换内容会拒绝。
- 创建 POST 不自动重试。5xx、断线、非字符串任务编号都可能意味着已受理，因此先保留未知状态。
- 查询临时失败继续保留原任务；客户端有限退避重试，等待结束后保留“继续获取”入口。
- 上游失败与可恢复的网络问题分开显示；不能把空文件、HTML 错误页或未完成任务当成功视频。
- H3 恢复查询使用任务创建时的配置版本。更改当前绑定不会让旧 H3 任务跑到新供应商。
- 取消等待只取消客户端等待，不等于供应商取消生成。积分沿用现有“预扣、成功结算、失败/取消退款；继续获取时再次预扣，最终只结算成功一次”的客户端流程。
- 若任务一直 `unknown`，技术人员按 `LiveVideoJob` 的用户、请求编号与创建时间核对供应商。只有核实了同一用户同一任务的上游编号后才能人工关联并继续查询；不得为了恢复而随意创建第二条收费任务。
- 旧 Wan 任务没有 H3 的配置版本存档，继续查询仍依赖旧 Wan 绑定/密钥。切换前先取回旧任务；需要恢复旧 Wan 时临时恢复原绑定。不要将旧 Wan 编号迁移成 H3 编号。
- 老的 `high/medium/good` 三个 100 分规格保留用于兼容历史任务，不显示为新的三档，历史账单、余额不重算。

## 回滚

停止发起新 H3 任务后，先保存并取回已完成结果，保留任务表、配置历史与 MinIO 文件。回退桌面端/管理端/服务端到上方基线或上一构建包；后台恢复原 Wan 绑定。价格可运行 `node scripts/point-prices-backup.cjs --restore /安全目录/prices-before-h3.json` 恢复备份。

不删除已有迁移记录，不删 `LiveVideoJob` 表，不清空用户数据。旧服务器可以忽略新增表与规格。回退服务端期间 H3 继续获取接口不可用；待需要恢复时，重新启用本分支服务端查询原任务即可，不能重新发起收费生成替代。
