# 需求梳理版 · 管理员管理

> 源需求：[需求-管理员管理.md](../requirements/需求-管理员管理.md)  
> 状态：可评审 / 可排期  
> 结论摘要：后台登录身份从 `User.role=admin` 拆到独立 `AdminUser` 表。新增「管理员管理」页对后台账号做增删改查；「用户管理」收窄为 Electron 的 `User`。JWT 隔离（`/admin/auth/*` + `JWT_ADMIN_SECRET`）保留。

---

## 1. 产品定位

| 项 | 说明 |
|----|------|
| 产品 | 织序后台（`admin/`）的管理员账号管理 + 登录主体切换 |
| 使用者 | 已持有有效**后台 JWT** 的运营（`AdminUser`） |
| 管理对象 | 后台登录账号（新表 `AdminUser`），与 Electron `User` 分表、分密码 |
| 协作项目 | **Admin** 新页面与用户管理页收敛；**NestJS** 新表、登录改查 `AdminUser`、管理员 CRUD API |
| 不做什么 | 不物理删除；不做 RBAC；不让管理员表账号登录 Electron；不改全局 `request/shared.ts` |
| 成功标准 | 种子管理员可登录后台；可增删改查其他管理员；Electron 用户不能进后台；管理员账号不能进 Electron |

## 2. 用户与用例

| ID | 角色 | 用例 | 优先级 | 验收要点 |
|----|------|------|--------|----------|
| UC-01 | 管理员 | 打开「管理员管理」分页列表 | Must | 展示 id、邮箱、用户名、状态、创建时间；无密码哈希；无 Electron `role` |
| UC-02 | 管理员 | 按关键字（邮箱/用户名）、状态筛选 | Must | 组合查询正确；重置后恢复分页 |
| UC-03 | 管理员 | 新建管理员（邮箱+密码，用户名可选） | Must | 创建即 `active`；可用该邮箱密码走 `/admin/auth/login`；**不能**用该账号走 `/auth/login`（除非另有 Electron `User`） |
| UC-04 | 管理员 | 编辑用户名 / 邮箱 | Must | 表内唯一冲突可读；保存后列表刷新 |
| UC-05 | 管理员 | 启用 / 禁用 | Must | 禁用后 `/admin/auth/login` 失败；启用后可登录；后台 refresh 作废 |
| UC-06 | 管理员 | 重置密码 | Must | 管理员设新密码（长度同现规则）；该管理员后台 refresh 全部作废 |
| UC-07 | 系统 | 保护最后一个 active 管理员 / 禁止禁自己 | Must | 不能禁用当前登录自己；不能禁用库中最后一个 `active` 管理员 |
| UC-08 | 未登录 / 桌面端 JWT | 调管理员或用户管理接口 | Must | 无后台 JWT → 401；Electron JWT → 401；无列表数据 |
| UC-09 | 管理员 | 侧栏进入「管理员管理」 | Must | `views/manage/admin` 两层路由；`zh-cn` 文案齐全；JQ* 布局 |
| UC-10 | 管理员 | 用管理员表账号登录后台 | Must | `/admin/auth/login` 只查 `AdminUser`；不再要求 `User.role=admin` |
| UC-11 | Electron 用户 | 用桌面端账号登录后台 | Must | 仅存在于 `User`、不在 `AdminUser` → 后台登录失败（401，防枚举口径同现网） |
| UC-12 | 开发者 | seed 写入管理员表 | Should | `ADMIN_SEED_EMAIL` / `ADMIN_SEED_PASSWORD` 幂等 upsert `AdminUser`，**不**再给 `User` 标 `admin` |
| UC-13 | 管理员 | 「用户管理」不再管后台身份 | Must | 去掉角色筛选/表单/列；不能把 Electron 用户「提成管理员」 |
| UC-14 | 管理员 | 改管理员邮箱 | Should | 随 PATCH；表内唯一；改后用新邮箱后台登录 |
| UC-15 | 模板开发 | mock 下列表可点 | Could | `VITE_AUTH_MOCK=Y`；验收不以 mock 为准 |
| UC-16 | 管理员 | 物理删除 / 导出 | Won't | 本期不做 |

## 3. 功能拆解

### 3.1 Admin（后台前端）

| 模块 | 范围 | 备注 |
|------|------|------|
| 新页面 | `views/manage/admin/index.vue` | `JQCustomPage` + `JQSearch` + `JQDataTable` + `JQDialogForm`；无 PageMenu Tab |
| API | `service/api` 管理员模块 + `typings/api` | 走现有 `nest.ts`；不改 `shared.ts` |
| 用户管理页 | 去掉角色相关 UI | 仍调 `/admin/users*`，只当 Electron 用户 CRUD |
| 登录 | 已接 `/admin/auth/*` | 登录成功主体改为 `AdminUser`（映射仍用现 `boUser` 形状） |
| i18n | `route.manage_admin` + `page.manage.admin` | 至少 `zh-cn` |
| 权限 UI | 不新增 privilege 树 | 能进后台 = 持有后台 JWT |

### 3.2 NestJS（服务器）

| 模块 | 范围 | 备注 |
|------|------|------|
| 数据 | 新表 `AdminUser` + `AdminRefreshToken` | 迁移；不把管理员挂到 `User.refreshTokens` |
| 登录 | `/admin/auth/*` 改查 `AdminUser` | JWT `sub` = `AdminUser.id`；`aud=admin`；密钥仍 `JWT_ADMIN_SECRET` |
| CRUD | `/admin/admins*` | 列表/创建/PATCH/重置密码；禁用=删 |
| 守卫 | `JwtAdminAuthGuard` 即足够 | 去掉对 `User.role` 的 `RolesGuard` 依赖 |
| 用户管理 API | `/admin/users*` 去掉 `role` 入参/出参（或忽略写入） | 禁自己/最后 admin 保护**移出**本模块（对象已不是同一张表） |
| Seed | 只写 `AdminUser` | 与 Electron `User` 互不改写 |

### 3.3 现有能力对照

| 已有 | 本需求用法 |
|------|------------|
| `/admin/auth/*` + `JWT_ADMIN_SECRET` | 保留协议；换身份表 |
| `/admin/users*` | 继续管 Electron `User`，去掉角色语义 |
| `User.role` / `UserRole` | **不再用于后台鉴权**；列可暂留以免大迁移 Electron 代码 |
| 用户管理页 | 收敛为桌面端账号管理 |
| privilege stub | 保持 |

## 4. 非功能需求

| ID | 类型 | 要求 |
|----|------|------|
| NFR-01 | 安全 | 后台接口只接受后台 JWT；密码不明文回传；禁用/重置后该管理员 refresh 失效 |
| NFR-02 | 隔离 | `AdminUser` 与 `User` 分表；邮箱各表内唯一，**允许跨表相同** |
| NFR-03 | 协议 | 继续独立 Nest 客户端；不改 `shared.ts` |
| NFR-04 | 可维护 | API 只从 `@/service/api` 引入；Swagger `/docs` 为契约 |
| NFR-05 | 可观测 | 管理员写操作记安全日志（无密码） |
| NFR-06 | i18n | 默认 `zh-cn`；生产无 `console.log` |
| NFR-07 | 文档 | 产品文档只在 `admin/docs` |

## 5. 端到端流程（目标态）

```text
seed → AdminUser(active)
  → POST /admin/auth/login（查 AdminUser）→ 后台 JWT
  → 打开「管理员管理」→ 列表/筛选/新建/编辑/启停/重置密码
  → 新建的管理员可用后台登录，不能用 /auth/login 进 Electron
打开「用户管理」→ 只见 Electron User；无角色字段
  → 新建的桌面端用户可用 /auth/login，不能用 /admin/auth/login
Electron JWT 调 /admin/* → 401
仅有 User、没有 AdminUser 的邮箱调 /admin/auth/login → 失败
```

## 6. 范围 In / Out

| In | Out |
|----|-----|
| Prisma `AdminUser` + `AdminRefreshToken` 与迁移 | 物理删除、导出 |
| `/admin/auth` 改查管理员表 | RBAC 菜单裁剪 |
| `/admin/admins*` CRUD | 管理员登录 Electron / 用户登录后台 |
| 管理员管理页 + 用户管理去角色 | 改全局 `shared.ts` |
| seed 写 `AdminUser` | 把存量 `User.role=admin` 自动灌进管理员表（见 Q-A3：默认不灌） |
| 最后管理员 / 禁自己（针对 `AdminUser`） | 新的邮箱验证码流 |

## 10. 风险摘要

| 风险 | 等级 | 对策 |
|------|------|------|
| 登录仍查 `User` 导致种子失效 | 高 | `/admin/auth` 与 Jwt 策略同步改 `AdminUser` |
| 管理员 refresh 仍写在 `User.RefreshToken` | 高 | 新表 `AdminRefreshToken`，`sub` 用管理员 id |
| 误把存量 `User.role=admin` 当后台账号 | 中 | Q-A3 不自动灌；README 写明需 seed |
| 用户管理仍暴露 `role` 造成提权错觉 | 中 | API+UI 同时去掉角色 |
| 禁掉唯一管理员无法再登录 | 高 | 服务端最后管理员保护 |
| 两表同邮箱运营混淆 | 低 | 文档与列表标题写清「后台账号 / 桌面端账号」 |
