# 需求梳理版 · 积分统计

> 源需求：[需求-统计.md](../requirements/需求-统计.md)  
> 状态：文档齐（梳理 / 技术设计 / 开发计划 / 自测），Q-01～Q-06 已锁定。未说「按计划开发」前不写业务代码  
> 结论摘要：在「积分」下新增「积分统计」页，并在首页用三张 ECharts 看同一口径。三个维度都统计 **已完成消费的净消耗**（`consume` + `completed`）。用户用横向柱状看 Top 10，角色用横向柱状看绝对消耗（一名用户可绑多角色，不能画成占比环），功能用环形图看互斥占比。充值、调账、退还中的预扣不进这三张图。

## 0. 已拍板（相对源需求）

| 项 | 结论 |
|----|------|
| 统计什么 | **净消耗** = 时间范围内 `type=consume` 且 `status=completed` 的 `amount` 之和。预扣中、已退还、退还行、后台调账、充值都不计 |
| 角色指什么 | 业务角色 `Role`（`RoleUser`）。`User.role` 枚举 `user \| admin` 不参与 |
| 功能指什么 | `PointFeature.menuCode`，即现有创作功能。不按规格（优/中/良）再拆 |
| 多角色 | 用户当前每条 `RoleUser` 绑定都 **整笔计入** 该角色。角色之间会重复，各项之和可以大于总净消耗 |
| 无角色 | 没有任何 `RoleUser` 的消耗归入合成行「未分配角色」 |
| 时间 | 统计页默认可改，默认 **近 30 天**（按流水 `createdAt`）；首页三张图固定同一窗口，不单独改时间 |
| 用户图 | 横向柱状，**Top 10**，按净消耗降序 |
| 角色图 | 横向柱状（含「未分配角色」）。不用环形图 |
| 功能图 | 环形图，中心写本期总净消耗。消耗为 0 的功能不进环，在统计页表格里显示 0 |
| 图表库 | 用现成 `echarts` + `src/hooks/common/echarts.ts` 的 `useEcharts`，不新引入图表库 |
| 首页 | 保留欢迎 Banner；下面欢迎大卡片换成三张图 |

## 1. 产品定位

| 项 | 说明 |
|----|------|
| 产品 | 后台看积分花到了谁、哪类角色、哪个创作功能 |
| 使用者 | 持后台 JWT 的运营 |
| 管理对象 | 只读聚合，不改余额、不改流水 |
| 协作项目 | **NestJS** 聚合接口；**Admin** 统计页 + 首页三图。Electron 无页面 |
| 不做什么 | 充值额、调账额、当前余额分布、按规格下钻、导出、实时推送、后台 RBAC |
| 成功标准 | 同一时间范围内，首页三图与统计页三块数字一致；功能占比之和为 100%；退还掉的预扣不出现在消耗里 |

## 2. 为什么是这三张图

三张图回答的问题不一样，所以不能都用饼图，也不能都用同一张图硬套。

| 维度 | 数据形状 | 图 | 不用另一种的原因 |
|------|----------|----|------------------|
| 用户 | 人多、名字长，运营要看「谁花得最多」 | **横向柱状 Top 10** | 饼图超过几片就不可读；Top 10 也不是全体的互斥切分 |
| 角色 | 角色少，但一名用户可绑多个角色，一笔消耗会进多个角色 | **横向柱状** | 环形图默认各块加起来是 100%。重复计入后占比会超过 100%，环是错的 |
| 功能 | 每笔已完成消费只有一个 `menuCode`，全体消耗被功能切完 | **环形图** | 这是唯一适合看占比的维度。中心放总净消耗，避免只看到比例、看不到量 |

统计页上功能仍有表格，0 消耗的功能留在表里，不塞进环。角色表只给绝对值和有消耗的用户数，**不给「占比」列**，避免和重复计入打架。

首页三列等宽会挤。用户名需要横向空间，排成：

```text
桌面：用户 Top 10（较宽） | 角色柱状
      功能环形（单独一行，宽度约一半居中或与上排对齐）
窄屏：三张上下堆叠
```

具体栅格在技术设计里定，原则是用户图比角色图宽，功能环不要拉成全宽长条。

## 4. 功能拆解

### 4.1 统计口径

只加总下面这一类流水：

```text
PointLedger.type   = consume
PointLedger.status = completed
PointLedger.createdAt 落在所选时间范围内（含起、含止）
```

| 流水 | 是否计入 | 原因 |
|------|----------|------|
| 消费已完成 | 计入 `amount` | 这才是花掉的积分 |
| 消费预扣中 `pending` | 不计 | 还可能退 |
| 消费已退还 `refunded` | 不计 | 钱已退回；对应 `refund` 行也不再减一次，避免减两次 |
| `refund` | 不计 | 已用「排除 refunded 消费」表达退还 |
| `admin_increase` / `admin_decrease` | 不计 | 没有功能，也不是用户创作消耗 |
| `recharge` | 不计 | 入账不是消耗 |
| 单价为 0 的已完成消费 | 计入笔数，金额加 0 | 功能表要能看到「用过但免费」 |

时间取流水 `createdAt`（预扣写下的时间，不是后来确认的时间）。本期接受这个偏差。

**角色归集（当前绑定，不是消耗发生时的快照）：**

- 一笔消费的 `userId` 当前绑了角色 A、B → 这笔 `amount` 同时进 A 和 B。
- 后来解绑的角色不再带上历史消耗；后来新绑的角色会带上该用户在时间范围内的全部已完成消费。
- 禁用角色：绑定还在就计入，表格标「已禁用」。
- 用户一个 `RoleUser` 都没有 → 「未分配角色」。

这个规则会让「改用户角色」回头改历史统计。本期不做消耗当时的角色快照（流水表上也没有）。

**功能归集：** 按该笔 `menuCode` 汇总。对不上 `PointFeature` 的历史码单独一行，名称用码本身，不丢数。

### 4.2 三个维度

| 维度 | 图表 | 统计页表格 | 排序 |
|------|------|------------|------|
| 用户 | 横向柱状 Top 10。类目是用户名，空用户名用邮箱 | 本期净消耗 > 0 的用户；关键字搜邮箱/用户名 | 净消耗降序，相同再按笔数 |
| 角色 | 横向柱状。类目是角色名 +「未分配角色」。0 消耗的角色也画出来 | 全部角色 + 未分配（未分配仅当金额或笔数 > 0 才出现） | 净消耗降序 |
| 功能 | 环形图。只画净消耗 > 0 的功能；图例带名称和积分；中心是总净消耗 | 全部 `PointFeature`，外加落单的未知 `menuCode` | 功能 `sort`，未知码放最后 |

Top 10 之外的用户只在统计页表格里，不进首页图。

### 4.3 积分统计页

路由相对 `views/`：`points/stats/index.vue`，侧栏标题「积分统计」，父级仍是「积分」。

组件：`JQCustomPage` + `JQSearch`（时间）+ 三块卡片。每块上面是 §4.2 的图，下面是表。用户表用 `JQDataTable` 分页；角色表、功能表行数少，不分页。

筛选项只有时间，三个维度共用：

| 预设 | 范围 |
|------|------|
| 近 7 天 | 含今天共 7 个自然日 |
| 近 30 天 | 默认 |
| 近 90 天 | |
| 全部 | 不传起止 |
| 自定义 | 起止日期，止不得早于起 |

空范围：三张图空态文案「该时间范围内没有已完成的积分消耗」，表为空表，总净消耗显示 0。

### 4.4 首页

`views/home/index.vue`：

- `HeaderBanner` 保留。
- `ContentInfo` 欢迎大卡片换成三张图卡片，数据与统计页默认「近 30 天」相同。
- 卡片标题：按用户、按角色、按功能。副标题统一「近 30 天净消耗」。
- 不在首页做筛选、不做表格、不跳转要求本期也不做（Could：卡片标题链到统计页）。

### 4.5 NestJS（梳理级）

只读，`JwtAdminAuthGuard`。不改 `PointLedger` 表结构。

| 接口 | 返回 | 谁用 |
|------|------|------|
| 汇总 | 总净消耗、`byUser` Top 10、`byRole`、`byFeature` | 首页三图；统计页的图和角色/功能表 |
| 用户明细分页 | 关键字、页码、与汇总相同的时间参数 | 统计页用户表 |

字段到技术设计再定死。汇总里的用户行至少要有展示名、净消耗、笔数；角色行要有名称、是否禁用、是否「未分配」、净消耗、有消耗用户数；功能行要有名称、`menuCode`、净消耗、笔数。

用户分页与 Top 10 必须用同一套口径，避免首页第 1 名和表格第 1 名不一致。

### 4.6 Admin 约束

- 文案 `zh-cn`。
- 请求走 `@/service/api`。
- 图表只走现有 `useEcharts`。`BarChart`、`PieChart` 已在 `echarts.ts` 注册。
- 不改 `request/shared.ts`。
- 权限 UI 仍 stub；拦截在 Nest。

## 5. 主流程

```text
运营打开首页
  → 三张图请求「近 30 天」汇总
  → 用户柱：消耗最高的 10 人
  → 角色柱：每个当前角色的消耗（多角色用户重复计入）
  → 功能环：各创作功能占已完成消费的比例，中心是总净消耗

运营打开积分统计，把时间改成近 7 天
  → 三块图和三张表一起换成近 7 天
  → 用户表可搜某个邮箱，分页看完所有有消耗的人
```

## 8. 待澄清

| ID | 问题 | 默认（若未答复） | 影响 |
|----|------|------------------|------|
| Q-01 | 多角色用户的消耗是否整笔计入每个当前角色？ | **是**。因此角色用柱状图，不画占比 | 角色柱的合计可以大于总净消耗 |
| Q-02 | 角色按当前绑定，还是按消费发生时的角色？ | **当前绑定**。流水不补快照 | 改绑角色后，历史图会变 |
| Q-03 | 默认时间？ | 统计页 **近 30 天**，可改；首页固定近 30 天 | 首页与统计页默认打开时一致 |
| Q-04 | 自然日按哪个时区切？ | **Asia/Shanghai** | 近 N 天的起止 |
| Q-05 | 净消耗为 0 的用户要不要出现在用户表？ | **不要**。只列 > 0 | 表不会被「从没花过」的人撑满 |
| Q-06 | 首页欢迎大卡片？ | **换成三张图**，Banner 保留 | 首页布局 |

## 10. 风险摘要（梳理级）

| 风险 | 等级 | 对策方向 |
|------|------|----------|
| 把退还和已退还消费各减一次，消耗被减成负数或偏小 | 高 | 只加 `consume + completed` |
| 角色画成环形图，占比加起来超过 100% | 高 | 角色固定柱状图，表上不放占比 |
| 运营以为角色统计是「当时他是这个角色」 | 中 | 页上短说明：按当前绑定，多角色会重复计入 |
| 首页三列等宽把用户名挤没 | 中 | 用户图更宽；类目用用户名，过长截断，悬停看全名和邮箱 |
| `createdAt` 是预扣时间，确认跨天时归到前一天 | 低 | 本期接受；不改表 |
| 用户很多时一次查出全部再在前端排序 | 中 | Top 10 与分页都在服务端算 |
