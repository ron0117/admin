## 3. 功能拆解

### 3.1 计价模型（菜单 + 规格）

只对创作叶子菜单配价。一行 = `menuCode + specKey → 单价（非负整数）`。

| menuCode | 名称 | 规格行 `specKey` / 展示名 | 数量（客户端） |
|----------|------|---------------------------|----------------|
| `generate.create.inspire` | 灵感创作 | `default` / 默认 | 本次生成张数，无则 1 |
| `generate.create.fission` | 去同质化裂变 | `default` / 默认 | 本次裂变张数 |
| `generate.create.scene-renew` | 原景出新 | `default` / 默认 | 本次张数，无则 1 |
| `generate.create.free` | 自由创作 | `default` / 默认 | 本次张数，无则 1 |
| `generate.create.live` | live 图生成 | `high` 优 / `medium` 中 / `good` 良 | 本次张数 |
| `generate.create.copywrite` | 文案仿写 | `default` / 默认 | 本次生成条数 |

```text
总积分 = 该行单价 × 数量
```

- 历史 `generate.manage.history`、磁盘清理 `generate.manage.disk-cleanup`：**不配、不扣、CTA 不加积分后缀**。
- 运营不能增删功能行，只能在弹窗里改各规格单价与备注（行来自种子）。
- live 现有本地常量 `15/10/5` 仅作迁移前占位；上线后 **以后台配置为准**。

**CTA 文案（动作文案保持现状）：**

| 场景 | 按钮 |
|------|------|
| 灵感创作 | `开始创作 · {n} 积分` |
| 去同质化裂变 | `一键裂变 · {n} 积分` |
| 原景出新 | `一键出新 · {n} 积分` |
| 自由创作 | `生成图片 · {n} 积分` |
| live | `生成 live 图 · {n} 积分` |
| 文案仿写 | `AI 生成仿写 · {n} 积分` |

### 3.2 扣费与幂等

```text
用户点击生成
  → 客户端生成（或沿用本次）requestId
  → Nest 预扣：余额 >= 快照总价？
        否 → 拒绝，不生成
        是 → 扣余额，记流水（消费/预扣成功），返回快照单价与总价
  → 客户端带着同一 requestId 走现有生成
  → 成功：流水保持已完成（或确认）
  → 失败 / 明确取消：Nest 退还（同 requestId 只退一次）
  → 传输失败客户端重试预扣或确认：按 requestId 幂等，不二次扣
```

| 规则 | 说明 |
|------|------|
| 用户点两次 | 两个 `requestId` → 两笔、扣两次 |
| 服务器失败后重试 | 同一 `requestId` → 一笔、扣一次 |
| 余额不足 | 拦截，桌面提示，不创建生成任务 |
| 单价快照 | 预扣当时的配置写入流水；之后改价不影响本笔 |
| 超时未决 | 预扣后长期无成功/失败回执：按 Q-02 超时自动退还（TTL 技术设计定） |

Electron 现有创作请求已带 `requestId`（灵感/裂变/出新/自由/live 等），本需求把它升级为 **计费幂等键**，不强行新发明一套 ID。

### 3.3 NestJS

| 模块 | 范围 | 备注 |
|------|------|------|
| 余额 | `User` 增加积分余额（整数 ≥0） | 注册/后台创建默认 0；变更必须与流水同一事务 |
| 功能设置 | 按菜单聚合：备注 + 多规格单价，唯一 `(menuCode, specKey)` | 种子 6 菜单；管理端改规格单价与备注，不能增删功能行 |
| 流水 | 不可改历史金额；类型含消费、退还、后台调增、后台调减 | `requestId` 在消费类唯一 |
| 管理 API | 功能设置列表/按菜单保存、流水分页筛选、用户调账 | `JwtAdminAuthGuard` |
| 桌面 API | `me` 带 `points`；拉功能设置；预扣；成功确认；失败退还 | 桌面 JWT；预扣/退还按 `requestId` 幂等 |
| 用户列表 | `/admin/users` 增加 `points` | 调账独立接口，避免和改资料混在一个 PATCH 里误触 |

### 3.4 Admin 页面设计（按现有组件）

对齐现有「用户 / 角色」：**侧栏父级「积分」下两个二级页**（`views/` 两层，不用 PageMenu）。用户调账留在现有用户列表，不新开第三页。

建议路径：

| 路由（相对 `views/`） | 页面 | 组件组合 |
|----------------------|------|----------|
| `points/settings/index.vue` | 功能设置 | `JQCustomPage` + `JQDataTable` + `JQDialogForm` |
| `points/records/index.vue` | 积分流水 | `JQCustomPage` + `JQSearch` + `JQDataTable` |
| `user/list/index.vue`（加列） | 用户管理 | 现有 + 积分列 + `JQDialogForm` 调账 |

权限 UI 仍 stub；真正拦截在 Nest。API 只走 `@/service/api`。i18n `zh-cn`。不改 `request/shared.ts`。

#### A. 功能设置

**一功能一行**（6 行），**不分页**（`showPagination=false`）。不在单元格里改价。无新增/删除（行来自种子）。

| 列 | 来源 | 交互 |
|----|------|------|
| 功能 | 菜单名 | 只读 |
| 积分 | 规格摘要，如 `默认 10` 或 `优 15 / 中 10 / 良 5` | 只读 |
| 备注 | `remark` | 只读，空则 — |
| 更新时间 | `updatedAt` | `formatTime` |
| 操作 | — | 「修改」打开弹窗 |

表头仅默认刷新。无 `JQSearch`。

**「修改」→ `JQDialogForm`（宽约 560px）**

| 字段 | `type` | 规则 |
|------|--------|------|
| 功能名称 | `input` disabled | 只读，来自菜单名 |
| 菜单码 | `input` disabled | 只读，`menuCode` |
| 单价（非 live） | `inputNumber` | `prop: unitPoints`；步长 1，最小 0，必填整数 |
| 优 / 中 / 良（仅 live） | `inputNumber` ×3 | `unitHigh` / `unitMedium` / `unitGood`；同上 |
| 备注 | `textarea` | 选填，最长 200 字，给运营自己看 |

校验失败留在弹窗。保存成功 toast + 关窗 + 刷新表。一次提交写该功能全部规格单价与备注。

#### B. 积分流水（本需求要新开的查询页）

与用户列表同一套：`JQSearch` 查询/重置 + `JQDataTable` 分页。只读，无新增。

**筛选项（`JQSearch` + `FormItem`）：**

| 字段 | `type` | 说明 |
|------|--------|------|
| 用户 | `input` | 邮箱 / 用户名关键字 |
| 类型 | `select` | 消费 / 退还 / 后台调增 / 后台调减 |
| 功能 | `select` | 6 个创作菜单；可空=全部 |
| 状态 | `select` | 已完成 / 已退还 / 预扣中（若有） |
| 时间 | `datetimerange` | 创建时间 |

**表格列：**

| 列 | 说明 |
|----|------|
| 时间 | `formatTime` |
| 用户 | 邮箱；可附用户名 |
| 类型 | `ElTag`：消费红、退还绿、调增绿、调减橙 |
| 功能 / 规格 | 后台调账可空 |
| 数量 | 消费/退还有值 |
| 变动 | `+10` / `-10`，颜色区分 |
| 余额（变动后） | 该笔完成后的余额 |
| 请求 ID | 等宽小字，方便排障；调账可空 |
| 状态 | 预扣中 / 已完成 / 已退还 |
| 备注 | 调账原因；消费失败原因可写 |

默认按时间倒序；分页 20 条。点行不强制弹详情（列已够对账）；若请求 ID 过长，操作列可「复制 ID」（小按钮，非新组件）。

不做：导出（`FileExportDialog` 有但本期不用）、批量勾选。

#### C. 用户列表加调账

在现有 `JQDataTable` 增加：

- 列「积分」：`points`
- 操作「调整积分」→ `JQDialogForm`（宽约 480px）

弹窗字段：

| 字段 | `type` | 规则 |
|------|--------|------|
| 方向 | `radio` | 增加 / 减少 |
| 数量 | `inputNumber` | 正整数，必填 |
| 备注 | `textarea` | 必填，便于流水审计 |

提交成功 toast + 刷新列表。调减大于余额：接口拒绝，表单提示。

## 5. 端到端流程（目标态）

```text
运营登录 Admin
  → 功能设置：点 live 行「修改」，在弹窗改优/中/良单价与备注并保存
  → 用户管理：给某用户 +100 积分（流水：后台调增）
Electron 用户登录
  → 顶栏积分 100；创作页 CTA 显示当前总价
  → 点「开始创作 · 10 积分」
      余额够 → 预扣 10 → 生成
      生成失败 → 退还 10 → 顶栏回 100
      生成成功 → 顶栏 90；后台流水一条消费
  → 网络闪断后客户端用同一 requestId 重试 → 不再扣
  → 再点一次生成 → 新 requestId → 再扣一笔
运营打开积分流水：能按用户/类型/功能/时间对上上述记录
```

| AC-02 | 流水可按用户、类型、功能、时间筛选分页；调账与消费都能查到 | UC-03/05 |

| AC-04 | 桌面顶栏积分与 `me` 一致；CTA 为「动作 · n 积分」且随数量/规格变 | UC-06/07 |
| AC-05 | 余额不足不生成并提示 | UC-08 |
| AC-06 | 两次点击两笔；同一 requestId 重试一笔 | UC-09～11 |
| AC-07 | 生成失败或取消后退还；改价不影响进行中任务 | UC-12/13 |
| AC-08 | 无后台 JWT 不能改价/调账/查流水；桌面 JWT 不能调管理接口 | UC-15 |
| AC-09 | 页面用 JQ*；`zh-cn`；侧栏可进功能设置与流水 | §3.4 |
| AC-10 | 无支付充值、无邀请、无导出 | UC-17～19 |

## 10. 风险摘要（梳理级）

| 风险 | 等级 | 对策方向 |
|------|------|----------|
| 只改余额不写流水 / 退还漏账 | 高 | 事务 + 状态机；退还也幂等 |
| 把「点两次」做成只扣一次 | 高 | 幂等键是 `requestId`，不是用户+菜单 |
| live 本地 15/10/5 与后台不一致 | 中 | 上线后以后台为准；无配置则按 Q-01 当 0 |
| 预扣成功生成通道无回调 | 中 | Q-02 TTL 退还 |
| 自由创作 / 文案仿写无统一 CTA 壳 | 中 | 在现有按钮文案上拼接，不先做大改版 |
| 运营以为改价即时打进正在跑的任务 | 低 | 功能设置页可加一句说明；流水存快照 |
