# 需求梳理版 · 卡密充值

> 源需求：  
> - [需求-卡密充值.md](../requirements/需求-卡密充值.md)  
> - [nestjs/docs/requirements/需求-卡密充值.md](../../../nestjs/docs/requirements/需求-卡密充值.md)  
> - [electron/docs/requirements/需求-卡密充值.md](../../../electron/docs/requirements/需求-卡密充值.md)  
> 状态：可评审 / 可排期  
> 结论摘要：运营在 Admin **批量生成**带 **自由积分面额** 的卡密，**列表展示完整卡密**；导出给 **wzyp 等店铺**线下售卖，系统 **只跟踪未兑换/已兑换**；Electron **一步兑换**入账；Nest 提供 Admin + 桌面 API 与 `recharge` 流水；**Ping++ 应用内支付本期不扩展**。

---

## 0. 已拍板（会话澄清）

| 项 | 结论 |
|----|------|
| 状态机 | **未兑换 → 已兑换**（兑换即验码+入账）；**不在系统内持久化「已出售」** |
| 「已出售/未出售」文案 | 产品曾提两态；与 **export_shop** 一致：**未出售 ≈ 未兑换**（含已导出但未核销）；**已兑换** 后不可再用 |
| 售出跟踪 | 卡密 **导出给店铺** 售卖；**无 wzyp 回调/API**；卖出与否 **不进库** |
| 面额 | 生成时 **自由填写到账积分**（正整数），**不绑定** RechargePackage 档位 |
| Admin 卡密展示 | 列表 **完整明文**（内网运营） |
| Electron | **一步「兑换」**；保留外链店铺窗；Ping++ 档位 **保持隐藏** |
| Ping++ | **卡密替代主路径**；Ping++ 订单/Webhook **本期不扩展**（代码可暂留） |
| 入账 | 兑换成功写 **`PointLedgerType.recharge`**，与卡密记录关联 |
| 文档 | 新建 **需求-卡密充值** 三端 requirements + 本梳理版 |

## 1. 产品定位

| 项 | 说明 |
|----|------|
| 产品 | 积分卡密：运营生成 → 店铺售卖 → 用户在桌面 **兑换** 到账 |
| 使用者 | 运营（生成、列表、导出）；Electron 登录用户（购买外链 + 兑换） |
| 管理对象 | 卡密、兑换记录、用户积分、`recharge` 流水 |
| 协作 | **Admin** 卡密管理 UI；**Nest** 生成/列表/兑换 API；**Electron** 店铺窗 + 兑换表单 |
| 与串接三方关系 | 取代 Ping++ **用户侧**充值路径；Admin「充值管理/充值记录」可 **演进为卡密** 或并存展示，以实现为准（见 §3.4） |
| 成功标准 | 运营可生成并查到明文卡密；用户兑换后积分增加且卡密变已兑换；重复兑换拒绝；Admin 可按状态/时间筛选 |

## 2. 用户与用例

| ID | 角色 | 用例 | 优先级 | 验收要点 |
|----|------|------|--------|----------|
| UC-01 | 运营 | 批量生成卡密 | Must | 数量、到账积分、可选批次备注；生成成功返回/可列表查看 |
| UC-02 | 运营 | 卡密分页列表 | Must | 完整卡密、积分、状态、生成时间；已兑换含兑换时间、用户账号 |
| UC-03 | 运营 | 筛选卡密 | Must | 至少：状态、生成时间范围；Should：积分、卡密关键字 |
| UC-04 | 运营 | 导出卡密 | Should | CSV 或 Excel；供店铺上架；不改变兑换状态 |
| UC-05 | 运营 | 查看兑换记录 | Must | 账号、卡密、积分、兑换时间；可与 UC-02 同页 Tab 或独立菜单 |
| UC-06 | Electron 用户 | 外链店铺购买 | Must | `RECHARGE_CARD_SHOP_URL` 打开店铺窗（已实现） |
| UC-07 | Electron 用户 | 输入卡密兑换 | Must | 成功刷新积分；失败提示；空卡密前端校验 |
| UC-08 | Electron 用户 | 重复提交已兑卡密 | Must | 服务端拒绝；客户端不重复加积分 |
| UC-09 | 系统 | 并发双兑同一卡密 | Must | 仅一笔成功；事务 + 行锁/唯一状态变更 |
| UC-10 | 系统 | 兑换限流 | Should | 防暴力猜码（用户/IP 维度，阈值设计阶段定） |
| UC-11 | 未授权 | Admin 卡密 API | Must | 无后台 JWT → 401 |
| UC-12 | 未授权 | 桌面兑他人无关 | Must | 兑换仅作用于当前 JWT 用户余额 |
| UC-13 | 运营 | Ping++ 档位新购 | Won't | 本期不扩展 |
| UC-14 | 系统 | wzyp 自动标记已出售 | Won't | 不对接 |

## 3. 功能拆解

### 3.1 Admin · 卡密管理

| 能力 | 说明 |
|------|------|
| 生成 | 弹窗：数量（上限技术设计）、到账积分、备注；提交后刷新列表 |
| 列表列 | 卡密（明文）、积分、状态（未兑换/已兑换）、生成时间、兑换时间、兑换账号 |
| 操作 | 导出（Should）；**不提供** C 端「作废」除非后续需求（Could） |
| 路由 | 建议：`积分管理` 下 **卡密管理**；与「充值管理（Ping++ 档位）」并存或隐藏旧入口（实现期与产品确认一次 UI 入口） |

### 3.2 Admin · 兑换记录

与积分流水 `recharge` 对齐：列表字段满足对账；账号 **懒加载** 筛选（与充值记录一致）。

### 3.3 Electron · 账号页

| 区块 | 说明 |
|------|------|
| 当前积分 | 已有 |
| 购买 | 「前往店铺购买」 |
| 兑换 | 单行/多行输入 +「兑换」；成功后 `authGetStatus` 更新积分 |

### 3.4 与现有 Ping++ 模块

| 模块 | 本期 |
|------|------|
| RechargePackage / Admin 档位 | 不扩展；入口可隐藏 |
| RechargeOrder / Webhook | 不扩展 |
| 桌面 Ping++ 档位 UI | 保持关闭 |
| PointLedger.recharge | **沿用**，卡密兑换写入 |

## 4. 非功能需求

| 项 | 要求 |
|----|------|
| 安全 | 卡密明文存库仅限受控 Admin；生产依赖后台鉴权与 HTTPS |
| 性能 | 批量生成单请求上限（如 ≤500 张/次，设计阶段可调） |
| 审计 | 生成操作可记 `createdByAdminId`（Should） |
| 兼容 | 不影响积分 hold/commit/调账 |

---

## 5. 端到端流程

```
运营 Admin 生成 N 张卡密（积分 P）
    → 列表查看 / 导出
    → 运营在 wzyp 店铺上架（系统外）
用户 Electron 店铺购买得卡密（系统外）
    → 账号页输入卡密 → Nest 兑换
    → 事务：卡密=已兑换，User.points += P，PointLedger(recharge)
    → Electron 刷新积分
```

## 6. 范围

| In | Out |
|----|-----|
| 生成、列表、筛选、导出、兑换、流水 | wzyp 售中/售后 API |

| Admin 兑换记录查询 | 用户端兑换历史页（Could 后续） |
| | 卡密退款/作废（本期不做） |
| | 库内只存哈希（与拍板相反） |

## 8. 验收标准

| AC | 描述 | 对应用例 |
|----|------|----------|
| AC-01 | 生成 10 张 100 积分卡密，列表可见 10 条未兑换、明文一致 | UC-01～02 |

## 9. 风险摘要

| 风险 | 对策 |
|------|------|
| 明文卡密泄露 | 严格 Admin 权限；后续可改脱敏策略 |
| 暴力猜码 | 限流 + 足够熵（卡密长度） |
| 与 Ping++ 代码并存混淆 | 文档与菜单标明「卡密为主」；计划期梳理废弃项 |
