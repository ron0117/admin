# 需求梳理版 · 角色管理

> 源需求：[需求-角色管理.md](../requirements/需求-角色管理.md)  
> 状态：可评审 / 可排期  
> 结论摘要：Nest 种子「生图」菜单树；角色勾选菜单（勾父=全开）；Electron 用户多角色、权限并集。后台做角色 CRUD + 配置页 + 用户列表绑角色。桌面端本期按 `/auth/me` 裁剪生图导航。后台管理员 RBAC 仍不做。

---

## 1. 产品定位

| 项 | 说明 |
|----|------|
| 产品 | 织序后台配置 **Electron 菜单权限**；桌面端按权限显示生图 |
| 使用者 | 持后台 JWT 的运营（配角色/用户）；Electron 登录用户（被授权） |
| 管理对象 | 业务 `Role` + 菜单目录 + `User`↔`Role`；不是 `AdminUser` |
| 协作项目 | **NestJS** 表与 API；**Admin** 角色页/用户页；**Electron** 导航裁剪 |
| 不做什么 | 后台自身 RBAC；菜单管理 CRUD；按钮/数据权限；物理删除；改 `shared.ts` |
| 成功标准 | 后台能建角色并勾生图树；用户多角色；桌面端按并集隐藏/显示生图及子菜单 |

## 2. 用户与用例

| ID | 角色 | 用例 | 优先级 | 验收要点 |
|----|------|------|--------|----------|
| UC-01 | 运营 | 打开角色分页列表 | Must | 名称、状态、创建时间；无内部无关字段 |
| UC-02 | 运营 | 新建 / 编辑角色（名称、备注） | Must | 名称必填且唯一；创建即 `active` |
| UC-03 | 运营 | 启用 / 禁用角色 | Must | 禁用后：已绑用户立即失去该角色菜单（并集重算）；不能物理删 |
| UC-04 | 运营 | 打开角色配置，勾选菜单树 | Must | 树含父「生图」+ 现有子项；勾父=全开（含日后新增子节点语义见 Q-R2）；可只勾部分子项；保存后可读回 |
| UC-05 | 运营 | 用户列表看到角色列 | Must | 展示该用户已绑 **active** 角色名称（多枚）；可筛选（Should 随列表） |
| UC-06 | 运营 | 创建/编辑用户时多选角色 | Must | 只可选 `active` 角色；保存后 `/auth/me` 菜单为并集 |
| UC-07 | 运营 | 侧栏进入角色管理 / 配置 | Must | 两层路由 + 配置能力（列表进配置或 PageMenu Tab）；JQ*；`zh-cn` |
| UC-08 | Electron 用户 | 无任何生图权限登录 | Must | 可登录；顶栏无「生图」；直达 `/generate/**` 回工作台 |
| UC-09 | Electron 用户 | 仅部分子菜单 | Must | 顶栏有生图；子导航只显示已授权项；未授权子路径回工作台 |
| UC-10 | Electron 用户 | 勾了父级「生图」 | Must | 现有全部生图子菜单可见（与勾全子项等价） |
| UC-11 | Electron 用户 | 多角色并集 | Must | 角色 A 灵感 + 角色 B 历史 → 两者都可见 |
| UC-12 | 系统 | 种子菜单树 | Must | migrate/seed 后菜单表有生图父+8 子；幂等 |
| UC-13 | 未登录 / 桌面 JWT | 调角色管理 API | Must | 无后台 JWT / Electron JWT → 401 |
| UC-14 | 开发者 | `/auth/me` 带菜单 | Must | 桌面端 JWT；返回并集菜单码（含父/子约定见设计）；无 `passwordHash` |
| UC-15 | 运营 | 禁用角色仍留用户绑定 | Should | 绑定行可保留；鉴权只计 `active` 角色 |
| UC-16 | 运营 | 角色名称搜索 | Should | 关键字过滤列表 |
| UC-17 | 模板 | mock 下列表 | Could | 验收不以 mock 为准 |
| UC-18 | 运营 | 菜单管理页 / 按钮权限 | Won't | 本期不做 |
| UC-19 | 运营 | 给管理员配这套角色 | Won't | `AdminUser` 不参与 |

## 3. 功能拆解

### 3.1 NestJS

| 模块 | 范围 | 备注 |
|------|------|------|
| 菜单 | `Menu`（code 唯一、parent、sort、name） | 种子写入生图树；无管理端 CRUD |
| 角色 | `Role`（name 唯一、remark、status active\|disabled） | 禁用≠删行 |
| 关联 | `RoleMenu`、`UserRole` | 多对多 |
| 管理 API | `/admin/roles*`、给角色设菜单、菜单树只读、给用户设角色 | `JwtAdminAuthGuard` |
| 用户 API | `/admin/users` 列表/详情/写带 `roles: {id,name}[]` | 创建/PATCH 收 `roleIds` |
| 桌面 API | `/auth/me` 增加 `menus: string[]`（或树） | 只算 active 角色 ∪ 菜单 |
| 旧列 | `User.role` 枚举 | 暂留，写路径不依赖 |

**本期种子树（code 建议，设计阶段可微调）：**

```text
generate                         生图
├─ generate.create.inspire       灵感创作
├─ generate.create.fission       去同质化裂变
├─ generate.create.scene-renew   原景出新
├─ generate.create.free          自由创作
├─ generate.create.live          live图生成
├─ generate.create.copywrite     文案仿写
├─ generate.manage.history       历史任务
└─ generate.manage.disk-cleanup  磁盘清理
```

### 3.2 Admin

| 模块 | 范围 | 备注 |
|------|------|------|
| 角色列表 | `views/manage/role` | JQ* 列表 + 新建/编辑弹窗 + 启停 |
| 角色配置 | 同模块配置页或 Tab | 菜单树勾选；`:close-on-click-modal="false"` |
| 用户页 | 列 + 表单单选改多选角色 | 调角色列表 + `roleIds` |
| API | `service/api` 经 `nest.ts` | 不改 `shared.ts` |
| i18n | `route.manage_role` + `page.manage.role` | 至少 zh-cn；zh-tw/en-us 同步 |

后台侧栏对运营仍全通（stub）。

### 3.3 Electron

| 模块 | 范围 | 备注 |
|------|------|------|
| 会话 | 登录 / me / 刷新后缓存菜单码 | 与现有 Nest JWT 会话一起 |
| 顶栏 | `SECTION_ITEMS` 中 `generate` | 无生图权限则不渲染 |
| 子导航 | `GENERATE_NAV` | 按子 code 过滤；空组不显示 |
| 路由 | `/generate/**` 守卫 | 无对应叶子权限 → 工作台 |
| 未入库 | 工作台 / 抖店 / 设置 | 本期不过滤 |

### 3.4 现有能力对照

| 已有 | 本需求用法 |
|------|------------|
| `AdminUser` + `/admin/auth` | 仅运营入口，不绑业务角色 |
| `/admin/users*` | 增加 `roleIds` / 角色展示 |
| `User.role` 枚举 | 忽略 |
| Electron `GENERATE_NAV` / `SECTION_ITEMS` | 与种子 code 对齐；运行时过滤 |
| privilege stub | 后台保持 |

## 4. 非功能需求

| ID | 类型 | 要求 |
|----|------|------|
| NFR-01 | 安全 | 角色/菜单写接口只接受后台 JWT；桌面 me 只返回自己的并集 |
| NFR-02 | 实时性 | 改角色菜单或用户角色后，已登录桌面端在 **下次 me/刷新或重新登录** 后生效（不强制踢 access） |
| NFR-03 | 协议 | Admin 走 `nest.ts`；不改 `shared.ts` |
| NFR-04 | 契约 | Swagger `/docs`；Electron 菜单码与种子一致 |
| NFR-05 | i18n | 后台默认 zh-cn；生产无 `console.log` |
| NFR-06 | 文档 | 只在 `admin/docs` |

## 5. 端到端流程（目标态）

```text
seed → Menu 生图树
运营后台登录 → 新建角色「生图运营」→ 配置勾选父级 generate
  → 用户管理给某 Electron 用户勾该角色
用户 /auth/login → /auth/me.menus 含 generate 及子码
  → 桌面顶栏出现生图，子导航全开

另：角色只勾「灵感创作」
  → 顶栏有生图，仅灵感创作；进裂变 URL → 回工作台

用户未绑角色或角色全禁用
  → 可登录，无生图顶栏
```

## 9. 验收标准

| ID | 标准 | 对应 |
|----|------|------|
| AC-01 | 可 CRUD 角色；名称唯一；禁用后该角色不再贡献菜单 | UC-01～03 |
| AC-02 | 配置树可勾父/子；回显正确；勾父=当前及后续子菜单全开 | UC-04/10、Q-R2 |
| AC-03 | 用户可绑多个 active 角色；列表能看出角色 | UC-05/06 |
| AC-04 | 无后台 JWT / 桌面 JWT 调 `/admin/roles*` 401 | UC-13 |
| AC-05 | `/auth/me` 菜单为并集；禁用角色不计入 | UC-11/14/15 |
| AC-06 | 无生图权限：无顶栏生图；直达 generate 回工作台 | UC-08 |
| AC-07 | 仅部分子权限：只显示对应子导航 | UC-09 |
| AC-08 | 种子后菜单树完整；角色管理侧栏可进；zh-cn；JQ* | UC-07/12 |

## 10. 风险摘要

| 风险 | 等级 | 对策 |
|------|------|------|
| 菜单 code 与 Electron path 对不齐 | 高 | 种子 code 对照 `GENERATE_NAV`；设计表一张映射 |
| 只存叶子、父勾语义丢失 | 中 | Q-R2：父码即子孙全开；me 服务端展开 |
| 运营以为改完桌面立刻变 | 中 | README/配置页提示需刷新或重登 |
| 无角色用户以为坏了 | 低 | 仍进工作台；无生图入口 |
| 与旧 `User.role` 混淆 | 中 | API 用 `roles[]` / `roleIds`，不用枚举 |
