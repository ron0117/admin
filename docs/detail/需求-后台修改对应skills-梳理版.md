# 需求梳理版 · 后台修改对应 skills

> 源需求：[需求-后台修改对应skills.md](../requirements/需求-后台修改对应skills.md)  
> 状态：可评审 / 可排期  
> 结论摘要：在现有「积分 → 功能设置」弹窗里，为 5 个图片生图功能各增加一段 skills 文本。文本存在 Nest `PointFeature` 上，桌面端沿用 `GET /point-features` 缓存。点击生图时，非空 skills 写在本地已有提示词前面，再经现有 nest-proxy 发给中转站。空文本不改变现有提示词。文案仿写、识图分析、历史与磁盘清理不配、不拼。

---

## 0. 已拍板（相对源需求）

| 项 | 结论 |
|----|------|
| skills 含义 | 一段提示词文本，不是 Cursor 技能文件 |
| 配置入口 | 现有功能设置「修改」弹窗，与积分、备注同一保存 |
| 粒度 | **一功能一段**；live 优/中/良共用，不按规格拆 |
| 覆盖功能 | 灵感创作、去同质化裂变、原景出新、自由创作、live 图 |
| 不覆盖 | 文案仿写、历史、磁盘清理、裂变识图分析、结果区智能裁剪识图 |
| 存储 | `PointFeature` 增加一列文本；不新建功能行 |
| 长度 | trim 后最多 **4000** 字；超出拒绝保存 |
| 空值 | trim 后为空 = 未配置；生图提示词与现在一致 |
| 拼接 | `后台文本 + 换行 + 该次发往中转站的本地提示词` |
| 裂变 | 只拼批量生图 prompt，不拼识图分析 |
| live | 只拼最终发给实况生成的 motion prompt |
| 自由创作 | 本地提示词 = 用户输入框内容 |
| 读取 | 桌面端用已有积分配置缓存；缓存没有该字段时按空处理，不阻断生图 |
| 权限 | 仅后台 JWT 可改；桌面 JWT 只读 |
| 生效 | 桌面端下次拉到配置后的新一次生图生效；进行中的请求不改写 |

## 1. 产品定位

| 项 | 说明 |
|----|------|
| 产品 | 织序生图提示词前缀：运营在后台按功能配置，桌面端生图时前置 |
| 使用者 | 后台运营（填写 / 清空 skills）；Electron 登录用户（点击生图，无感知拼接） |
| 管理对象 | 5 个图片功能各自的 skills 文本 |
| 协作项目 | **Admin** 功能设置弹窗与列表摘要；**NestJS** 字段、校验、读写接口；**Electron** 取配置并拼到出图请求 |
| 不做什么 | 不改积分计价与扣费；不改本地提示词模板正文；不让运营增删功能行；不做版本历史、多语言、按规格拆段 |
| 成功标准 | 运营能在配积分的同一弹窗保存 skills；桌面端对应功能生图请求的提示词以前缀开头，未配置时与现网一致 |

## 3. 功能拆解

### 3.1 配置对象

| menuCode | 名称 | 是否配置 | 接到后面的本地提示词 |
|----------|------|----------|----------------------|
| `generate.create.inspire` | 灵感创作 | 是 | `compileInspirePrompt` 结果 |
| `generate.create.fission` | 去同质化裂变 | 是 | 批量生图 `compileFissionBatchPrompt` 结果 |
| `generate.create.scene-renew` | 原景出新 | 是 | `compileSceneRenewPrompt` 结果 |
| `generate.create.free` | 自由创作 | 是 | 用户输入框 trim 后的提示词 |
| `generate.create.live` | live 图生成 | 是 | 发给实况 Provider 的 motion prompt |
| `generate.create.copywrite` | 文案仿写 | 否 | 保持现网 |

历史、磁盘清理不出现在功能设置，也不拼 skills。

### 3.2 后台

- 页面仍是 `views/points/settings`。
- 列表增加 skills 状态列，文案为「已配置」或「未配置」。
- 「修改」仍用 `JQDialogForm`。图片功能增加多行文本；文案仿写不显示该字段。
- 功能名、menuCode 仍只读。单价、备注规则不变。
- 保存仍走现有 `PATCH /admin/point-features/:menuCode`。

### 3.3 服务端

- `PointFeature` 增加可空文本列，存 trim 后的 skills；空则存空语义（技术设计定 `null` 或 `''`，对外都表示未配置）。
- 管理端 PATCH 接受该字段，`MaxLength(4000)`，先 trim。
- `GET /admin/point-features` 与 `GET /point-features` 都返回该字段。
- 种子不预填正文；已有行迁移后视为未配置。
- 不提供增删功能行接口。

### 3.4 桌面端

```text
点击生图
  → 用已缓存的 point-features，按 menuCode 取 skills
  → trim 后非空：prompt = skills + "\n" + 本地提示词
  → trim 后为空或缓存缺失：prompt = 本地提示词
  → 现有 nest-proxy / 生图通道发出
```

- 不新开 IPC；拼接发生在组 prompt 的调用侧（页面或 live 主进程发请求前，技术设计二选一并写死一处）。
- 重试、继续裂变沿用同一次已拼好的 prompt，不二次叠加前缀。
- 积分预扣、退还、CTA 文案不因本需求改变。

## 4. 非功能需求

| 项 | 要求 |
|----|------|
| 权限 | 写接口仅后台 JWT；读配置沿用现有桌面 JWT |
| 兼容 | 旧桌面端忽略新字段；新桌面端遇旧接口缺字段按未配置 |
| 语言 | 后台文案 `zh-cn` |
| 性能 | 不在每次点击时单独为 skills 打一次配置接口 |
| 安全 | skills 是运营可控提示词，按普通配置存储与下发，不进用户流水 |

---

## 5. 端到端流程

```text
运营打开功能设置 → 修改某图片功能
  → 填写 skills（可与积分、备注一起改）→ 保存
  → Nest 校验长度并写入 PointFeature
  → 列表显示已配置

桌面端已登录并持有功能配置缓存
  → 用户点击对应功能生图
  → 前缀 + 本地提示词
  → 中转站收到的是拼接后的 prompt
```

## 6. 范围

| In | Out |
|----|-----|
| 5 个图片功能的 skills 配置、存储、下发、生图前拼接 | 文案仿写、历史、磁盘清理 |
| 功能设置列表状态与弹窗回显 | 按规格、按用户、按版本配置 |
| 4000 字校验与清空 | 提示词模板在线编辑、替换本地模板 |
| 裂变只拼出图；live 只拼实况生成 prompt | 识图分析、智能裁剪分析 |
| 空配置保持现网 prompt | 改积分规则、改中转站协议 |

### MoSCoW

| 级别 | 内容 |
|------|------|
| Must | UC-01～UC-11 |
| Should | 列表状态列；超长在输入框侧给出字数 |
| Won't | UC-12、UC-13；历史版本；运营预览拼接结果 |

## 7. 待澄清

| ID | 问题 | 默认（未另行答复则按此设计） | 影响 |
|----|------|------------------------------|------|
| Q-01 | 拼接用一个换行还是空行 | **一个换行** `\n` | 中转站看到的分段 |
| Q-02 | 超长在弹窗拦截还是只靠接口 400 | **两边都拦**；接口为准 | UC-04 |
| Q-03 | 文案仿写以后要不要同一字段 | **本期不要** | 表字段可留空，界面不展示 |
| Q-04 | 进行中的裂变重试是否重新读配置 | **否**，沿用本轮已拼 prompt | 避免双前缀 |

## 9. 风险摘要

| 风险 | 等级 | 对策方向 |
|------|------|----------|
| 重试再次拼接导致前缀重复 | 高 | 只在首次组 prompt 时拼一次 |
| 裂变识图被误加前缀，分析结果变掉 | 高 | 只拼 `aiGenerateImage` 的 batch prompt |
| live 加在识图种子上，和「发给中转站的运动描述」不一致 | 中 | 加在 `provider.generate` 的 motion prompt |
| 旧客户端不认识新字段 | 低 | 字段可选，缺省当未配置 |
