# 需求梳理版 · 串接三方（Ping++ 充值）

> 源需求：[需求-串接三方.md](../requirements/需求-串接三方.md)  
> 状态：可评审 / 可排期  
> 结论摘要：通过 Ping++ 为 Electron 用户提供积分充值；Nest 创建 Charge、Webhook 验签入账并写 `recharge` 流水；Admin 配置充值档位（金额、基础/赠送积分、上架/排序）并查询充值订单；桌面新增与工作台同级的「账号」模块，内嵌 WebView 支付，**仅以 Webhook 加积分**，前端轮询订单状态。首期 Ping++ Test + 单渠道联调；**不限购**。

---

## 0. 已拍板（相对源需求与会话澄清）

| 项 | 结论 |
|----|------|
| 支付通道 | Ping++；Nest Server SDK + Webhook |
| 首期环境 | **Test 模式 + 单一支付渠道**联调；Live 与多渠道后续 |
| 入账 | **仅 Webhook 验签成功**后加积分；WebView 内支付完成页面不可信 |
| 桌面收银 | **必须内嵌 WebView** 打开 Ping++ 返回的支付凭据/URL |
| 桌面状态 | WebView 打开后 **轮询订单状态**；成功刷新 `/auth/me` 积分并关闭收银 UI |
| 顶栏用户区 | 点击进入 **账号** 模块；**退出登录在账号页内**（不再点击顶栏即退出） |
| 账号模块位置 | 与「工作台 / 生图 / 抖店 / 设置」同级；**排在「设置」之后** |
| 档位积分 | **基础积分 + 赠送积分**；到账 = 二者之和 |
| 档位运营 | **上架/下架、排序**；**不限购**（不做限购校验与配置 UI） |
| Admin 列表金额 | **充值额度、手续费、实际到账均为金额（元）**；到账积分单独展示 |
| 流水 | 扩展 `PointLedgerType` 增加 **`recharge`**；与充值订单关联 |
| 订单（默认） | 未支付约 **30 分钟**关单；Admin 可查待支付/成功/失败/关闭 |
| Admin 菜单 | 「积分管理」下：**功能设置 / 积分流水 / 充值管理（档位）/ 充值记录** |
| 权限 | 桌面账号 **不做** Admin 侧菜单权限；登录即可用 |
| 非目标 | 导出 Excel、改价审计、邀请/套餐/plan、用户端查自己充值流水页（本期仅 Admin 列表） |

## 1. 产品定位

| 项 | 说明 |
|----|------|
| 产品 | 织序积分充值：运营配档位，用户桌面付费，后台对账 |
| 使用者 | 后台运营（档位、查充值记录）；Electron 登录用户（看余额、充值） |
| 管理对象 | 充值档位、充值订单、用户积分余额、`recharge` 流水 |
| 协作项目 | **Admin** 充值管理 + 充值记录；**NestJS** Ping++、订单、Webhook、加积分；**Electron** 账号页、WebView 支付、轮询 |
| 与积分模块关系 | 在已有 `User.points`、预扣/调账/流水之上 **增量**；原「支付充值不做」范围由本需求覆盖 |
| 成功标准 | 运营可配档位且桌面只看到已上架档位；用户 WebView 付完（Test 可模拟）后 Webhook 入账、顶栏积分更新；运营可按账号与时间查订单与金额字段 |

## 3. 功能拆解

### 3.1 充值档位（Admin · 充值管理）

| 字段（产品） | 说明 |
|--------------|------|
| 支付金额 | 用户应付（元）；展示与 Ping++ `amount` 一致（分为单位存库） |
| 基础积分 | 到账基础部分 |
| 赠送积分 | 额外赠送；展示「实得 = 基础 + 赠送」 |
| 上架状态 | 下架：Admin 可见，桌面接口不返回 |
| 排序 | 数字越小越靠前 |

交互：列表 + 新增/编辑弹窗（`JQDialogForm`）；路由层与 `points/settings`、`points/records` 并列，命名见技术设计。

### 3.2 充值记录（Admin）

- 布局：`JQCustomPage` + `JQSearch` + `JQDataTable`（对齐 `views/points/records`）。
- 筛选项：账号（远程搜索 `GET /admin/users?keyword=`）、时间范围、可选状态。
- 列（Must）：账号（邮箱/用户名）、充值额度、手续费、实际到账、到账积分、订单状态、创建/支付时间、商户订单号（可复制）。

**金额口径（已拍板）**

| 列 | 含义 |
|----|------|
| 充值额度 | 用户支付订单金额（元） |
| 手续费 | 渠道/Ping++ 侧扣费（元）；无则展示 0 |
| 实际到账 | 净入账金额（元）；与 Ping++ 对账字段对齐，技术设计定计算公式 |

### 3.3 NestJS（摘要）

- 表：`RechargePackage`、`RechargeOrder`（含 Ping++ charge id、order_no、各金额字段、状态）。
- 桌面：`GET` 已上架档位；`POST` 创建订单（返回 WebView 所需凭据）；`GET` 订单详情/状态。
- 公开：`POST /webhooks/pingpp`（或等价路径）验签、更新订单、事务内 `User.points` + `PointLedger(recharge)`。
- 定时或扫描：关闭超时待支付订单。
- 环境变量：Ping++ API Key、App ID、RSA 私钥、Webhook 公钥等（Test 首期）。

细节见 [nestjs 梳理版](../../../nestjs/docs/detail/需求-串接三方-梳理版.md)。

### 3.4 Electron（摘要）

- 新增 section `account`（图标/文案「账号」），路由 `pages/account/...`，默认页展示积分与档位。
- `UserStatus`：已登录 → `router.push` 账号默认页；退出移至账号页。
- 充值：选档位 → IPC → Main 调 Nest 创建订单 → **Main 或专用窗口内 WebView** 加载支付 URL。
- 轮询：Renderer 或 Main 定时查订单直到 `paid` / `failed` / `closed` / 超时。
- Renderer **不**持有 Ping++ Secret；不写「支付成功即加积分」。

细节见 [electron 梳理版](../../../electron/docs/detail/需求-串接三方-梳理版.md)。

### 3.5 与现有积分能力边界

| 能力 | 本需求 | 现网 |
|------|--------|------|
| 创作预扣 hold/commit/refund | 不变 | 不变 |
| 后台调账 | 不变 | 不变 |
| 积分流水页 | 不变；`recharge` 类型可在流水中展示（Should，与充值记录页分工：记录页看订单，流水看账本） | — |
| 功能设置 | 不变 | 不变 |

## 4. 非功能需求

| 项 | 要求 |
|----|------|
| 安全 | Webhook 必须验签；订单号全局唯一；加积分与改订单同一事务 |
| 幂等 | Ping++ 事件 id 或 charge id 去重 |
| 部署 | Webhook 需公网 HTTPS（开发可用隧道）；密钥仅 env |
| 兼容 | 旧桌面包无账号模块；不破坏现有登录与积分展示 |
| 语言 | Admin 默认 `zh-cn` |
| 性能 | 账号远程搜索防抖；轮询间隔 2–3s，支付窗关闭即停 |

## 5. 端到端流程

```text
运营 Admin 充值管理
  → 配置档位（金额、基础/赠送积分、上架、排序）→ Nest 持久化

Electron 用户 账号页
  → 拉已上架档位 + 当前积分
  → 选档位 → Nest 创建 RechargeOrder + Ping++ Charge(Test)
  → WebView 打开 charge 支付 URL
  → 前端轮询订单状态

Ping++ Webhook → Nest
  → 验签 → 订单 paid → 事务：加 User.points + PointLedger(recharge)
  → 返回 2xx

Electron 轮询到 paid
  → GET /auth/me 刷新积分 → 提示成功 → 关 WebView
```

## 9. 风险摘要

| 风险 | 等级 | 对策 |
|------|------|------|
| Webhook 不可达导致永不入账 | 高 | 公网 URL + 轮询仅 UX；以 Webhook 为准 |
| WebView 与渠道兼容性 | 中 | 首期单渠道；H5 页内支付 |
| 重复入账 | 高 | 事件/charge 幂等表或唯一约束 |
| 顶栏行为变更用户困惑 | 低 | 账号页明确「退出登录」 |
