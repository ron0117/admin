# 自测方案 · 角色管理

> 对齐：[需求-角色管理-梳理版](../detail/需求-角色管理-梳理版.md)、[技术设计-角色管理.md](../design/技术设计-角色管理.md)、[开发计划-角色管理.md](../plan/开发计划-角色管理.md)

---

## 1. 测试范围

| 纳入 | 不纳入 |
|------|--------|
| Menu/Role 种子、`/admin/roles*`、`/admin/menus/tree`、用户 `roleIds` | 菜单管理 CRUD、按钮权限、后台 RBAC |
| `login`/`refresh`/`me` 的 `menus[]` 展开（父=子孙、叶子带祖先） | JWT 写入 menus；改完立刻踢 access |
| 后台角色页 + 配树；用户多选/筛选角色 | mock 列表（UC-17） |
| Electron：生图顶栏、子导航、直达守卫 | 工作台/抖店/设置裁剪 |
| 禁用角色不贡献菜单；绑定行可保留 | 物理删除角色/菜单 |
| 管理员登录与 `AdminUser` 回归 | 改 `shared.ts`、新 privilege 树 |

## 2. 环境与前置

| 项 | 要求 |
|----|------|
| Nest | `npx prisma migrate deploy` 含角色菜单表；**重新** `npx prisma db seed`（菜单 9 节点 + 原 AdminUser） |
| Admin | `VITE_AUTH_MOCK=N`；种子管理员登录 |
| Electron | 指向同一 Nest；**本需求改过的桌面端**（旧包不读 `menus` 仍会全开生图） |
| 账号 | ① 运营 AdminUser ② 无角色 Electron 用户 ③ 可绑角色的 Electron 用户（后台创建即可） |
| Swagger | `http://localhost:3000/docs` tag `admin-roles` / `admin-users` / `auth` |

**接口速查**

| 能力 | 方法 | Path |
|------|------|------|
| 菜单树 | GET | `/admin/menus/tree` |
| 角色 CRUD | GET/POST/PATCH/GET | `/admin/roles` `/admin/roles/:id` |
| 角色菜单 | PUT | `/admin/roles/:id/menus` |
| 用户绑角色 | GET/POST/PATCH | `/admin/users`（`roles` / `roleIds` / query `roleId`） |
| 桌面会话 | POST/GET | `/auth/login` `/auth/refresh` `/auth/me`（含 `menus`） |
| 后台登录 | POST | `/admin/auth/login`（行为不变） |

**生图 code（须与种子一致）**

`generate` 及 8 子：`generate.create.inspire|fission|scene-renew|free|live|copywrite`、`generate.manage.history|disk-cleanup`。

## 4. 通过 / 失败

| 结论 | 条件 |
|------|------|
| **通过** | Must+Should 用例均过；e2e 绿；typecheck 过；未改 `shared.ts`；Electron 按 `menus` 裁剪 |
| **失败** | 勾父 me 缺子码；只勾叶子顶栏无生图；无角色仍显示生图（新桌面端）；桌面 JWT 能调 `/admin/roles`；禁角色仍贡献菜单；管理员无法登录；用户列表不能多选角色 |

已知限制（不挡通过）：运营改权限后，桌面在下次 me/刷新/重登前仍用旧 `menus`；未升级的旧 Electron 仍会显示全部生图。

---

## 5. 回归要点

- `/admin/auth/*`、`/admin/admins*`、管理员管理页
- `/admin/users` 创建/启停/重置密码仍可用；枚举 `User.role` 不再出现在后台 UI
- `/auth/register|login|refresh` 与 tasks；后台 JWT 仍不能调 `/tasks`
- Electron 未入库分区导航与登录/注册/验邮
