## 1. 测试范围

| 纳入 | 不纳入 |
|------|--------|
| Nest `/admin/users*`、RolesGuard、seed、禁用/重置后的登录与 refresh | 物理删除、导出、RBAC 菜单裁剪、`plan`、Electron |
| Admin：`VITE_AUTH_MOCK=N` 登录映射、用户列表 CRUD 页、zh-cn、JQ* | 列表 mock（UC-15，Could） |
| 最后 admin / 禁自己、非 admin 无法后台登录、桌面端 JWT 调管理接口 401、响应无密码哈希 | Access 黑名单（禁用后 access 短窗口，本期接受） |
| 静态：未改 `request/shared.ts`、无新 privilege 树 | 性能压测、生产 CORS 白名单精细化 |

## 2. 环境与前置

| 项 | 要求 |
|----|------|
| Nest | `nestjs/apps/nest-api` 可连 Postgres；`npx prisma migrate deploy` 已执行 |
| Seed | `ADMIN_SEED_EMAIL` / `ADMIN_SEED_PASSWORD` 已 seed 出 `admin`+`active`（UC-13） |
| Admin | `admin/` 下 `pnpm i`、`pnpm dev`；`.env`：`VITE_AUTH_MOCK=N`、`VITE_NEST_BASE_URL`（或 `/proxy-nest`） |
| 浏览器 | Chromium 系；开发者工具看 Network |
| 第二账号 | 普通 `user`（可用后台创建或自助注册后激活）用于后台登录 403、桌面端 JWT 401 与改角色 |
| 前置完成 | 开发计划 M0～M4 已勾选；M1 接口集可在无 UI 时用 Swagger `http://localhost:3000/docs` |

**接口速查**

| 能力 | 方法 | Path |
|------|------|------|
| 登录 | POST | `/admin/auth/login` |
| 刷新 | POST | `/admin/auth/refresh` |
| 当前用户 | GET | `/admin/auth/me` |
| 登出 | POST | `/admin/auth/logout` |
| 列表 | GET | `/admin/users` |
| 创建 | POST | `/admin/users` |
| 更新 | PATCH | `/admin/users/:id` |
| 重置密码 | POST | `/admin/users/:id/reset-password` |
| 删除 | — | **无**（Won't） |

| 用例 ID | 步骤 | 期望 | 追溯 |
|---------|------|------|------|
| TC-AUTH-01 | 按 README/seed 执行 seed 后 `POST /admin/auth/login` 用种子邮箱密码 | 200，`user.role=admin`，`status=active`，返回 access/refresh（`aud=admin`，与桌面端 token 不同） | UC-13 AC-09 |
| TC-AUTH-02 | Admin `VITE_AUTH_MOCK=N`，登录页用同一账号 | 进入布局壳；请求 `/admin/auth/login`；token 为 Nest 后台 JWT（非 `mock-token-*`） | Q-01 |

### 3.4 接口：写操作与安全

| 用例 ID | 步骤 | 期望 | 追溯 |
|---------|------|------|------|
| TC-API-10 | `POST /admin/users`：email+password（≥8），不传 role | 201/200；`status=active`，`role=user`；**无需验证码** | AC-02 UC-03 |
| TC-API-11 | 用该邮箱密码 `POST /auth/login` | 登录成功 | AC-02 |
| TC-API-12 | 重复邮箱再创建 | 409 `EMAIL_TAKEN` | UC-11 |
| TC-API-13 | 用户名冲突 | 409 `USERNAME_TAKEN` | AC-03 UC-11 |
| TC-API-14 | PATCH 改 username、role；再 GET 列表 | 已更新；改角色后该账号调 `/admin/users` 权限立即变 | AC-03 UC-08 |
| TC-API-15 | PATCH 改 email（Should）后用新邮箱登录、旧邮箱失败 | 符合唯一约束 | UC-14 |
| TC-API-16 | PATCH `status=disabled`；该账号 login | 失败（禁用）；refresh 旧 token 失败 | AC-04 UC-05 |
| TC-API-17 | 再 PATCH `status=active` 后 login | 成功 | AC-04 |
| TC-API-18 | 自助 `POST /auth/register` 出 pending 用户；管理员 PATCH `status=active` | 无需验证码可 login | AC-05 UC-06 |
| TC-API-19 | `reset-password` 后：旧 refresh 调 `/auth/refresh` 失败；新密码 login 成功 | 符合 | AC-06 UC-07 |
| TC-API-20 | admin 对**自己** PATCH `status=disabled` 或 `role=user` | 403 `CANNOT_MODIFY_SELF` | AC-07 UC-09 |
| TC-API-21 | 库中仅 1 个 active admin 时对其降级或禁用 | 403 `LAST_ADMIN` | AC-07 UC-09 |
| TC-API-22 | PATCH `status=pending_verification` | 400 `INVALID_STATUS` | 设计 §4.5 |
| TC-API-23 | 不存在的 id | 404 `USER_NOT_FOUND` | UC-11 |
| TC-API-24 | 密码 `<8` 创建或重置 | 400 校验错误 | UC-11 |
| TC-API-25 | 桌面端 user JWT 调 POST/PATCH/reset | **401** | AC-08 |

## 5. 通过 / 失败标准

| 结果 | 标准 |
|------|------|
| **通过** | 所有 Must 期望满足；AC-01～10 可勾选 |
| **有条件通过** | Must 通过；Should（改邮箱 TC-API-15、文档润色、typecheck）或 Could mock 未完成，且写入已知问题 |
| **失败** | 任一 Must 失败：无 JWT 登录、列表含哈希、非 admin 能拉列表、可禁自己/最后 admin、创建后不能登录、重置后旧 refresh 仍可用、页面无 JQ* 或改了 `shared.ts` |

**已知接受（不记失败）：** 禁用后未过期的 access 在 TTL 内仍可能调通非 refresh 接口。

缺陷记录建议：用例 ID、现象、复现、关联文件/接口、级别（Blocker/Major/Minor）。
