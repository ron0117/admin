## 2. 环境与前置

| 项 | 要求 |
|----|------|
| Nest | 本需求代码已启动；**不用** migrate |
| Admin | `VITE_AUTH_MOCK=N`；种子管理员登录 |
| 单测 | 在 `nestjs/apps/nest-api` 执行 `pnpm test -- point-stats.service.spec.ts points-pricing.spec.ts` |
| 页面 | Admin `pnpm typecheck`；`pnpm dev` 后侧栏能看到「积分统计」 |

**接口速查**

| 能力 | 方法 | Path |
|------|------|------|
| 三维度汇总 | GET | `/admin/points/stats?from&to` |
| 用户排行分页 | GET | `/admin/points/stats/users?from&to&keyword&page&pageSize` |

`from` / `to` 用上海墙钟 `YYYY-MM-DD HH:mm:ss.SSS`。不传表示不限制该边界。

页面数字必须等于**同一次**接口响应，不要对着流水页心算。口径对错看 §3.1 的样例和单测。

### 2.1 口径样例（单测数据，也可用 Prisma Studio 造一份再对 Swagger）

只看已完成消费。下面每一行是分组之后的用户，不是流水原文。

| 用户 | 当前角色 | 已完成净消耗 | 笔数 | 功能 |
|------|----------|--------------|------|------|
| U1 | 角色 A、角色 B | 100 | 2 | 灵感 100 |
| U2 | 无 | 40 | 1 | live 40 |
| U3 | 角色 A | 0 | 1 | 自由创作，单价 0 |
| U4 | 角色 D（已禁用） | 30 | 1 | 裂变 30 |

另有但不计：U1 的预扣中 50、U2 的已退还消费 20 及对应退还行、一笔调增 999、一笔充值 500。

| 检查点 | 期望 |
|--------|------|
| `total` | 170 |
| `byUser` 顺序 | U1 100、U2 40、U4 30；没有 U3 |
| 角色 A | 净消耗 100，笔数 3，有消耗用户数 2（U1+U3） |
| 角色 B | 100 / 2 / 1 |
| 角色 D | 30 / 1 / 1，`status=disabled` |
| 未分配角色 | 40 / 1 / 1 |
| 角色合计 | 100+100+30+40 = 270，大于 `total` |
| 功能 | 灵感 100、live 40、裂变 30、自由创作 0 且笔数 1；其余功能 0 |

Swagger 用后台 JWT。无这四名用户时，以单测绿代替本表前 8 行，页面用例仍要做。
