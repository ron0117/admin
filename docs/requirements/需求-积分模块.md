# 需求 · 积分模块

为 Electron 用户引入积分：后台配置创作功能消耗，桌面端生成时展示并真实扣费。充值、套餐、邀请好友本期不做，积分靠后台手工调账。

## 已锁定

| 项 | 结论 |
|----|------|
| 范围 | 功能设置 + CTA 展示 + 预扣/退还 + 用户余额 + 后台调账 + 积分流水 |
| 计价 | 菜单 + 规格单价；`总价 = 单价 × 数量` |
| 配价对象 | 仅 6 个创作菜单；历史任务 / 磁盘清理不配、不扣 |
| 获积分 | 新用户 0；后台加减。支付充值、邀请好友后续 |
| 功能设置页 | 一功能一行；操作列「修改」→ `JQDialogForm` 配积分与备注 |
| CTA | `{原动作} · {n} 积分`，例：`开始创作 · 10 积分` |
| 扣费 | 请求前预扣；失败/取消退还；余额不足拦截提示 |
| 幂等 | 每次点击新 `requestId` 扣一次；同一 ID 重试只算一次 |
| 改价 | Electron 下次拉取生效；进行中任务用开始时快照 |
| 文档 | 产品流水线 `admin/docs`；Nest 开发文档 `nestjs/docs` |

## 后台（Must）

- **功能设置**：表格列出 6 个创作功能；点修改弹窗配置规格单价（live 优/中/良）和备注
- **积分流水**：筛选 + 分页查询消费/退还/调账
- **用户列表**：展示余额；弹窗增加/减少积分（调减不得为负）

## 服务器（Must）

- 用户积分余额；功能规格配置；流水账
- 管理 API：功能设置、流水、调账
- 桌面 API：`me.points`、拉配置、hold / commit / refund（`requestId` 幂等）

## 桌面端（Must）

- 顶栏余额以后台为准
- 6 个创作页 CTA 标总价
- 生成前预扣；失败退还；不足拦截

## 明确不做

支付充值、套餐/`plan`、邀请好友、用户端流水、导出、历史/磁盘清理扣费、后台管理员 RBAC。
