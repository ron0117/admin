# 需求 · 管理员管理

后台登录账号与 Electron 用户**彻底分表、分密码**，互不借用。

## 已锁定

| 项 | 结论 |
|----|------|
| 身份模型 | 新增独立 `AdminUser`（或同等名）表，**不**再用 `User.role=admin` 作为后台登录条件 |
| 用户管理 | 只管理 Electron 的 `User`（桌面端账号）：列表/创建/编辑/启停/重置密码 |
| 管理员管理 | 新页面，只管理后台登录账号：增删改查 |
| 后台登录 | 继续 `/admin/auth/*` + `JWT_ADMIN_SECRET`；校验对象改为 `AdminUser`，不再读 `User` |
| 桌面端登录 | 继续 `/auth/*` + `JWT_SECRET`；只认 `User`。管理员表账号不能进 Electron |
| 邮箱 | 各表内唯一；**允许**与 Electron 用户邮箱相同（两套身份） |
| 删除 | 不物理删除，**禁用**；不能禁自己；不能去掉最后一个 `active` 管理员 |
| 创建 | 后台创建即 `active`，不走邮箱验证码 |
| 菜单权限 | 仍 stub 全通；能进后台的前提是持有有效后台 JWT |
| 文档位置 | 只放 `admin/docs`，不另起 nestjs 平行需求源 |

## 管理员管理页（Must）

- 分页列表，支持按邮箱/用户名、状态筛选
- 新建管理员（邮箱、密码、用户名可选）
- 编辑资料（用户名、邮箱）
- 启用 / 禁用
- 重置密码（管理员直接设新密码，并作废该管理员的后台 refresh）

## 用户管理配套调整（Must）

- 去掉「角色」筛选/表单（不再把 Electron 用户提成后台管理员）
- 接口不再依赖 `User.role` 做后台鉴权
- 种子管理员写入**管理员表**，不再往 `User` 写 `role=admin`

## 明确不做

- 物理删除、导出、RBAC 菜单裁剪
- 管理员账号登录 Electron，或 Electron 用户登录后台
- 改 Admin 全局 `{code,data}` 请求封装
