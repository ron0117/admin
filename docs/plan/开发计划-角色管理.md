# 开发计划 · 角色管理

> 对齐：[需求-角色管理-梳理版](../detail/需求-角色管理-梳理版.md)、[技术设计-角色管理.md](../design/技术设计-角色管理.md)  
> MVP：Must UC-01～14 + Should UC-15/16  
> 粗估：**2.5～3.5 人天**（Nest 表+API + Admin 角色页/用户绑角色 + Electron 导航裁剪）  
> **须用户再说「按计划开发」后才写业务代码**

跨项目：前缀 **N** = `nestjs/`，**A** = `admin/`，**E** = `electron/`。命令在对应项目根执行。

---

## 1. 里程碑

| 里程碑 | 目标 | 建议耗时 | 完成标志 |
|--------|------|----------|----------|
| M0 表与种子 | `Menu`/`Role`/`RoleMenu`/`UserRole` 迁移；生图 9 节点 seed | 0.4～0.6d | seed 后树接口能列出父+8 子 |
| M1 角色与会话 API | `/admin/roles*`、菜单树、`resolveMenus` 挂 login/me/refresh | 0.6～0.9d | Swagger 可见；勾父展开子孙；e2e 过 |
| M2 用户绑角色 | `/admin/users` 的 `roles`/`roleIds`/`roleId` 筛选 | 0.2～0.3d | 创建用户可绑多角色；禁用角色不进 me |
| M3 Admin 页 | 角色列表+配树；用户列表多选角色 | 0.5～0.8d | 侧栏可进；typecheck 过 |
| M4 Electron | `menus` 缓存；顶栏/子导航/守卫 | 0.5～0.8d | 无权限无生图；部分权限只显示对应项 |
| M5 收尾 | README、执行日志、对照 AC | 0.2～0.3d | AC 可勾选 |

**依赖：** M0 → M1 → M2；M3 依赖 M1（角色页）与 M2（用户页）；M4 依赖 M1；M5 依赖 M3+M4。  
**不可打乱：** 不得先改 Electron 藏菜单而 `me` 尚无 `menus`；不得页面先上却未 migrate。

Could（UC-17 mock 列表）不进 MVP。

## 2. 任务拆分（可勾选）

### M0 · Schema 与种子（UC-12）

- [ ] N0.1 Prisma：`RoleStatus`、`Menu`、`Role`、`RoleMenu`、`UserRole`；`User.userRoles`；migrate
- [ ] N0.2 `seed.ts` 幂等 upsert 技术设计 §5 九个 code；**不改** AdminUser seed 逻辑
- [ ] N0.3 e2e 内存 mock 补 `menu` / `role` / `roleMenu` / `userRole`（含 `$transaction`）
- [ ] N0.4 现有 `/auth/*`、admin 用户/管理员 e2e **回归仍通过**

### M1 · 角色 API 与 menus 下发（UC-01～04、10、13、14）

- [ ] N1.1 模块 `roles/`（可内含 menus tree）：挂 `AppModule`；Swagger tag `admin-roles`
- [ ] N1.2 `GET /admin/menus/tree`；`GET/POST /admin/roles`；`GET/PATCH /admin/roles/:id`；`PUT .../menus`
- [ ] N1.3 保存菜单规范化（有父则去掉子孙）；名称唯一 `ROLE_NAME_TAKEN`；非法 code `MENU_NOT_FOUND`
- [ ] N1.4 `resolveMenus(userId)`：active 角色并集 + 子孙 + 祖先
- [ ] N1.5 `login` / `refresh` / `me` 增加 `menus: string[]`（只增字段）
- [ ] N1.6 e2e：后台 JWT 才通；Electron JWT 401；勾 `generate` 后 me 含全部子码；只勾叶子 me 含 `generate`；禁用角色不计入

### M2 · 用户绑定（UC-05/06/15/16 接口侧）

- [ ] N2.1 DTO：列表出参 `roles`；`roleIds` 写入；query `roleId`；PATCH 省略 `roleIds` 不改绑定
- [ ] N2.2 绑禁用角色 → 400；只列 active 角色名
- [ ] N2.3 更新用户相关 e2e（绑多角色、筛选、禁用角色后 me 变）

### M3 · Admin 前端（UC-01～07、16）

- [ ] A3.1 `service/api/roles.ts` + `typings/api/roles.d.ts`；用户 API 类型补 `roles`/`roleIds`
- [ ] A3.2 `views/manage/role/index.vue`：JQ* 列表 CRUD；启停确认；「配置权限」对话框 `ElTree`；提示需桌面刷新/重登
- [ ] A3.3 elegant `manage_role`（routes/imports/transform/elegant-router.d.ts）+ i18n 三语 + `app.d.ts`
- [ ] A3.4 用户页：角色列、多选、Should 筛选 `roleId`
- [ ] A3.5 `pnpm typecheck`；无 `console.log`；不改 `request/shared.ts`；不新建 PRIV 树

### M4 · Electron（UC-08/09/11）

- [ ] E4.1 `shared/generate/menu-codes.ts`：path/scene ↔ code；与种子表一致
- [ ] E4.2 `AuthStatus` / 会话变更 / `auth-api-client` 解析 `menus`；缺省 `[]`
- [ ] E4.3 登录与启动（已有 session）调用 `GET /auth/me` 刷新 menus
- [ ] E4.4 `AppLayout` 过滤生图顶栏；`GenerateNav` 过滤叶子；空分组不渲染
- [ ] E4.5 `router/guards.ts`：无对应叶子的 `/generate/**` → 工作台
- [ ] E4.6 若 `AuthGetStatus` 等现有通道 payload 增加 `menus`，同步 `docs/IPC.md`（通道名可不变）

### M5 · 收尾

- [ ] T5.1 Nest / Admin / Electron README：seed 菜单、配角色、桌面须升级才藏菜单
- [ ] T5.2 `admin/docs/memory/执行日志-角色管理.md`
- [ ] T5.3 Nest `test:e2e`、Admin `typecheck`；人工对照 AC（Nest + Admin `VITE_AUTH_MOCK=N` + Electron 登录）

### 不在本计划

- 菜单管理页、按钮权限、后台 RBAC、抖店/设置裁剪、mock 列表、物理删除、JWT 写入 menus、改完立刻踢 access

## 3. 依赖顺序

```text
N0.* ──► N1.* ──► N2.* ──► A3.4
              │         └──► A3.1～A3.3
              └──► E4.* ────────────┐
                                    ▼
                              T5.*（M3+M4 后）
```

| 可并行 | 说明 |
|--------|------|
| A3.1～A3.3 与 E4 | 都只依赖 M1 的 `menus` / 角色 API |
| N2 与 A3.2 | 角色页可不绑用户；用户页必须等 N2 |

## 6. 风险与缓冲

| 风险 | 缓冲 | 应对 |
