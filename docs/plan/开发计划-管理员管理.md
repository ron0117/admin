# 开发计划 · 管理员管理

> 对齐：[需求-管理员管理-梳理版](../detail/需求-管理员管理-梳理版.md)、[技术设计-管理员管理.md](../design/技术设计-管理员管理.md)  
> MVP：Must UC-01～11、UC-13 + Should UC-12/14  
> 粗估：**2～3 人天**（Nest 迁移+登录换表 + Admin 新页 + 用户管理收敛）  
> **须用户再说「按计划开发」后才写业务代码**

跨项目：前缀 **N** = `nestjs/`，**A** = `admin/`。命令在对应项目根执行。

---

## 1. 里程碑

| 里程碑 | 目标 | 建议耗时 | 完成标志 |
|--------|------|----------|----------|
| M0 数据与登录换表 | `AdminUser` 迁移；`/admin/auth` 只认管理员表；seed 改写 | 0.6～0.8d | seed 后 `/admin/auth/login` 成功；`/auth/login` 用同一邮箱（无 User）失败 |
| M1 管理员 API | `/admin/admins*` + 保护 + e2e | 0.5～0.8d | Swagger 可见；AC-01～07 接口可测 |
| M2 用户管理 API 收敛 | `/admin/users` 去 role；去掉禁自己/最后 admin | 0.2～0.3d | 创建用户不能再传 role |
| M3 Admin 页面 | 管理员管理页 + 用户管理去角色 + i18n/路由 | 0.5～0.8d | 侧栏可进；typecheck 过 |
| M4 联调收尾 | README、执行日志、人工对照 AC | 0.2～0.3d | AC 可勾选 |

**依赖：** M0 → M1 → M3；M2 可与 M1 后半并行；M4 依赖前三项。  
**不可打乱：** 不得先改登录查表却未 migrate；不得页面先上但登录仍查 `User`。

Could（UC-15 mock）不进 MVP。

## 2. 任务拆分（可勾选）

### M0 · 表与登录（UC-10/11/12）

- [ ] N0.1 Prisma：`AdminUserStatus`、`AdminUser`、`AdminRefreshToken`；生成 migrate
- [ ] N0.2 `AdminAuthService` / `JwtAdminStrategy` / `me` 改查 `AdminUser`；refresh 走 `AdminRefreshToken`
- [ ] N0.3 后台 `request.user` 改为 `{ adminUserId, email }`；去掉登录路径对 `User.role` 的依赖
- [ ] N0.4 无记录与错密码统一 `AUTH_FAILED` 401；禁用 `ACCOUNT_DISABLED`
- [ ] N0.5 `prisma/seed.ts` 只 upsert `AdminUser`；`.env.example` / README 说明须重新 seed
- [ ] N0.6 现有 `/auth/*` e2e 回归仍通过

### M1 · 管理员 CRUD API（UC-01～08）

- [ ] N1.1 模块 `admins/`：controller / service / dto；挂 `AppModule`；Swagger tag `admin-admins`
- [ ] N1.2 `GET/POST /admin/admins`、`PATCH /admin/admins/:id`、`POST .../reset-password`
- [ ] N1.3 创建即 `active`；bcrypt 10；不返回 `passwordHash`
- [ ] N1.4 禁用/重置撤该管理员全部 `AdminRefreshToken`
- [ ] N1.5 禁自己 → `CANNOT_MODIFY_SELF`；最后 active → `LAST_ADMIN`
- [ ] N1.6 e2e：管理员全流程；Electron JWT 401；同邮箱 User 不能后台登录；禁自己/最后管理员

### M2 · 用户管理 API 收敛（UC-13）

- [ ] N2.1 List/Create/Update DTO 去掉 `role`；创建写死 `UserRole.user`
- [ ] N2.2 删除基于 `User` 的禁自己 / LAST_ADMIN
- [ ] N2.3 `/admin/users*` 仍要 `JwtAdminAuthGuard`；去掉 `RolesGuard`
- [ ] N2.4 更新用户管理相关 e2e（不再 promoteToAdmin、不再测 role 提权）

### M3 · Admin 前端（UC-01～09、13、14）

- [ ] A3.1 `service/api/admins.ts` + `typings/api/admins.d.ts`，经 index 导出
- [ ] A3.2 `views/manage/admin/index.vue`：JQ*；新建/编辑弹窗；重置密码弹窗；启停确认
- [ ] A3.3 elegant 路由 `manage_admin` + i18n `route.manage_admin` / `page.manage.admin`
- [ ] A3.4 用户管理页与 `admin-users` 类型去掉角色；登录映射不依赖 `user.role`
- [ ] A3.5 `pnpm typecheck` 通过；页面无 `console.log`；不改 `shared.ts`

### M4 · 收尾

- [ ] T4.1 Admin / Nest README：分表、重新 seed、两套登录邮箱可相同但密码独立
- [ ] T4.2 `admin/docs/memory/执行日志-管理员管理.md`
- [ ] T4.3 对照自测 Must 人工走通（需起 Nest + `VITE_AUTH_MOCK=N`）

### 不在本计划

- mock 列表、物理删除、导出、RBAC、自动迁移存量 `User.role=admin`、Access 黑名单
