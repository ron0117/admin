# 开发计划 · 积分模块

> 对齐：[需求-积分模块-梳理版](../detail/需求-积分模块-梳理版.md)、[技术设计-积分模块.md](../design/技术设计-积分模块.md)  
> Nest 细项亦可对照 [nestjs/docs/plan/开发计划-积分模块.md](../../../nestjs/docs/plan/开发计划-积分模块.md)  
> MVP：Must UC-01～15 + Should UC-16  
> 粗估：**5～7 人天**（Nest 2.5～3.5 + Admin 1～1.5 + Electron 1.5～2）  
> **须用户再说「按计划开发」后才写业务代码**

跨项目：前缀 **N** = `nestjs/`，**A** = `admin/`，**E** = `electron/`。命令在对应项目根执行。

---

## 1. 里程碑

| 里程碑 | 目标 | 建议耗时 | 完成标志 |
|--------|------|----------|----------|
| M0 表与种子 | `points` 列 + 功能/规格/流水；6 功能 seed | 0.5～0.7d | GET 功能设置 6 条；live 三档 |
| M1 计费 API | hold/commit/refund、TTL、me.points、调账、流水 | 1.2～1.8d | Swagger 齐；e2e 过 NA-04～10 |
| M2 Admin 页 | 功能设置弹窗、流水、用户积分列 | 0.8～1.2d | 侧栏可进；typecheck 过 |
| M3 Electron | IPC + CTA + 生成外包 hold | 1.2～1.8d | 不足拦截；双击两笔；失败退还 |
| M4 收尾 | README、IPC 文档、执行日志、对照 AC | 0.3～0.5d | AC 可勾选 |

**依赖：** M0 → M1 → M2 / M3（M3 不依赖 Admin 页，依赖 M1）；M4 依赖 M2+M3。  
**不可打乱：** 不得桌面先扣本地 localStorage；不得页面先上却未 migrate。

Won't（充值/导出/邀请）不进本计划。

---

## 2. 任务拆分（可勾选）

### M0 · Schema 与种子（UC-14/16）

- [ ] N0.1 Prisma：`User.points`；`PointFeature` / `PointFeatureSpec` / `PointLedger` + 枚举；migrate（含 consume `requestId` 部分唯一索引）
- [ ] N0.2 `seed.ts` 幂等 upsert 6 功能 + 规格，`unitPoints=0`；**不**插入历史/清理
- [ ] N0.3 已有用户回填 `points=0`；注册/后台创建默认 0
- [ ] N0.4 e2e mock Prisma 补新 model；旧 auth/admin e2e 回归绿

### M1 · Nest 计费 API（UC-03/05/06/08～15）

- [ ] N1.1 模块 `points/` 挂 `AppModule`；`PointsException`；Swagger tag `points` / `admin-points`
- [ ] N1.2 `GET/PATCH /admin/point-features`；非法 specs → `POINTS_INVALID_SPECS`
- [ ] N1.3 `GET /admin/point-ledgers` 筛选分页
- [ ] N1.4 `POST /admin/users/:id/points`；列表/详情带 `points`
- [ ] N1.5 `GET /point-features`；`POST /points/hold|commit|refund`
- [ ] N1.6 `PUBLIC_USER_SELECT` / login / me / refresh 带 `points`
- [ ] N1.7 条件更新防超扣；同 requestId 幂等；TTL `@nestjs/schedule`（`POINTS_HOLD_TTL_SEC`）
- [ ] N1.8 e2e：不足、双 ID、同 ID、退还幂等、commit 后禁 refund、改价不影响快照、TTL、鉴权隔离
- [ ] N1.9 `.env.example` + nest README 三五行

### M2 · Admin（UC-01～05、12）

- [ ] A2.1 `service/api/points.ts` + `typings/api/points.d.ts`；用户类型补 `points` / 调账
- [ ] A2.2 `views/points/settings/index.vue`：表 +「修改」`JQDialogForm`（live 三档）
- [ ] A2.3 `views/points/records/index.vue`：JQSearch + 分页表
- [ ] A2.4 用户列表积分列 + 调整弹窗
- [ ] A2.5 elegant 路由 `points_*` + i18n 三语 + `app.d.ts` 图标
- [ ] A2.6 `pnpm typecheck`；无 `console.log`；不改 `request/shared.ts`；无新 PRIV 树

### M3 · Electron（UC-06～13）

- [ ] E3.1 IPC 通道 + preload + `docs/IPC.md`
- [ ] E3.2 Main HTTP 客户端；`AuthStatus.points`；登录/me 刷新顶栏
- [ ] E3.3 拉 `/point-features`；CTA 文案与数量/清晰度联动
- [ ] E3.4 6 创作页：生成前 hold，成功 commit，失败/取消 refund
- [ ] E3.5 不足 toast 不发生成；历史/清理不 hold
- [ ] E3.6 live 扣费不再读本地 `LIVE_CLARITY_POINTS`

### M4 · 收尾

- [ ] T4.1 三项目 README：seed、调账、桌面须升级才扣费
- [ ] T4.2 `admin/docs/memory/执行日志-积分模块.md`（实现阶段再写）
- [ ] T4.3 Nest `test:e2e`、Admin `typecheck`；对照自测方案人工联调

### 不在本计划

- 支付充值、邀请、导出、用户端流水、菜单增删 API、`plan`、后台 RBAC

---

## 3. 依赖顺序

```text
N0 migrate/seed
  → N1 API + e2e
      → A2 后台页（可与 E3 并行）
      → E3 桌面扣费
          → T4 联调
```

---

## 4. MVP 对齐

Must UC-01～15、Should UC-16 全部进入 M0～M3。Could「复制 requestId」随流水页顺手即可，不单列里程碑。

## 5. 风险与缓冲

| 风险 | 缓冲 |
|------|------|
| 6 个创作页接入点分散 | E3.4 估上限；先抽 `holdGenerate()` 工具再改页 |
| Redis 与 TTL 无关但 e2e 环境不稳 | TTL 不依赖 Redis；单测可注入「现在时间」 |
| 联调三端 | +0.5d 人工（自测方案） |
