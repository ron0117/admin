## 1. 里程碑

| 里程碑 | 目标 | 建议耗时 | 完成标志 |
|--------|------|----------|----------|
| M0 Nest 底座 | 表、档位/订单 API、Ping++ 创建 Charge（Test） | 1.5～2d | migrate；Admin/桌面可读档位；可创建 pending 订单 |
| M1 Webhook 入账 | 验签、幂等、recharge 流水、关单任务 | 1～1.5d | e2e/Mock：Webhook 入账一次；重复/closed 不入账 |
| M2 Admin | 充值管理 + 充值记录 | 1～1.5d | typecheck；远程用户搜 + 时间筛 |
| M3 Electron | 账号 section + WebView + 轮询 | 1.5～2.5d | Test 联调：paid 后积分变；顶栏进账号 |
| M4 收尾 | AC 回归 | 0.5～1d | 积分 hold e2e 仍绿；自测方案走通 |

**依赖：** M0 → M1 →（M2 ∥ M3）→ M4。M2 与 M3 均依赖 M1 才能完成端到端验收，但 M2 档位页仅依赖 M0，M3 列表页可 Mock 订单状态先 UI。

**不可打乱：** 不得在 Webhook 入账完成前用 WebView 回调假加积分；Electron 须等 Nest `GET /recharge/orders/:id` 就绪。

Won't（导出、限购、退款、Live 多渠道）不进本计划。

## 3. 依赖顺序

```text
N0 migrate + 档位 + 创建订单
  → N1 Webhook + Admin 订单列表
      ├→ A2 Admin 页面（packages 可跟 N0 后并行）
      └→ E3 Electron（createOrder/getOrder 依赖 N0；paid 验收依赖 N1）
          → T4 联调
```

## 4. 并行建议

| 角色/人 | 可并行 |
|---------|--------|
| 后端 | N0→N1 串行 |
| 前端 Admin | A2.4 在 N0.3 后；A2.5 在 N1.5 后 |
| 桌面 | E3.1～3.2 与 N0 并行；E3.5～6 需 N0.5 |

## 6. 风险与缓冲

| 风险 | 缓冲 |
|------|------|
| Ping++ Test 渠道与 WebView 不兼容 | 预留 0.5d 换 `PINGPP_CHANNEL`；设计已限定 H5/WAP |
| Webhook 本地不可达 | dev 隧道；e2e 用 Mock |
| WebView 被当成支付成功 | 代码评审：禁止 did-finish-load 入账 |
| 重复 Webhook | N1.3 + 唯一 charge id |
| 估算偏紧 | 总缓冲约 1d 给 Ping++ 联调 |
