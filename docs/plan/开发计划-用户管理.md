跨项目：任务前缀 **N** = `nestjs/`，**A** = `admin/`。命令必须在对应项目根执行。

## 1. 里程碑

| 里程碑 | 目标 | 建议耗时 | 完成标志 | 状态 |
|--------|------|----------|----------|------|
| M0 Nest 鉴权补齐 | JWT 带 role；admin 守卫；CORS | 0.3～0.5d | 非 admin 调占位路由 403；admin 200 | 未开始 |
| M1 管理端用户 API | `/admin/users*` CRUD + 安全规则 + e2e | 1～1.5d | Swagger 可见；AC-01～08 接口侧可测 | 未开始 |
| M2 种子管理员 | 幂等 seed | 0.2～0.3d | 本地能登录一个 `admin`+`active` | 未开始 |
| M3 Admin 接 Nest | nest 客户端 + 登录/刷新映射 + 代理 | 0.5～0.8d | `VITE_AUTH_MOCK=N` 可登录并带 JWT | 未开始 |
| M4 用户管理页 | 列表 CRUD UI + i18n + 路由 | 0.5～1d | 侧栏可进；JQ* 页面对齐 AC-09 | 未开始 |
| M5 联调收尾 | 对照 AC 人工走通；README 联调说明 | 0.3～0.5d | AC-01～10 可勾选 | 未开始 |

**依赖：** M0 → M1 → M2；M3 依赖 M1（联调）但客户端骨架可与 M1 后半并行；M4 依赖 M3；M5 依赖 M1+M4。

Could（UC-15 mock 列表）不进 MVP，见 §2 M6。

## 2. 任务拆分（可勾选）

### M0 · Nest 鉴权补齐（UC-10）

- [ ] N0.1 `AuthUser` 增加 `role`；`JwtStrategy.validate` select `role`（每次读库，role 不写入 JWT）
- [ ] N0.2 新增 `Roles` 装饰器 + `RolesGuard`；非 admin → 403，无 JWT → 401
- [ ] N0.3 `main.ts`：`enableCors({ origin: true })`；Swagger 增加 tag `admin-users`
- [ ] N0.4 现有 `/auth/*` 与 tasks 等 e2e **回归仍通过**（`AuthUser` 扩字段不得破坏调用方）

### M1 · AdminUsers API（UC-01～11，UC-14）

- [ ] N1.1 模块 `admin-users/`：controller / service / dto；挂到 `AppModule`
- [ ] N1.2 `GET /admin/users`：page/pageSize/keyword/status/role；不返回 `passwordHash`/`plan`
- [ ] N1.3 `POST /admin/users`：直接 `active` + `emailVerifiedAt=now()`；默认 `role=user`；bcrypt 10；不走 `/auth/register`
- [ ] N1.4 `PATCH /admin/users/:id`：username / email / role / status（仅 active|disabled）；含改邮箱（UC-14）
- [ ] N1.5 `POST /admin/users/:id/reset-password`：写新 hash；撤销该用户全部 refresh
- [ ] N1.6 禁用时同样撤销 refresh；激活 `pending_verification` 时写 `emailVerifiedAt`
- [ ] N1.7 保护：禁/降级自己 → `CANNOT_MODIFY_SELF`；去掉最后 active admin → `LAST_ADMIN`
- [ ] N1.8 错误码与 HTTP 对齐技术设计 §6.3；写操作 `appLogger.security`（无密码）
- [ ] N1.9 e2e：admin 全流程；非 admin 403；最后 admin / 禁自己；列表不含 hash

### M2 · 种子（UC-13）

- [ ] N2.1 `prisma/seed.ts`：env `ADMIN_SEED_EMAIL` / `ADMIN_SEED_PASSWORD` 幂等确保一名 admin+active
- [ ] N2.2 `package.json` 配置 `prisma.seed`；`.env.example` 补变量说明（无真实密码提交）
- [ ] N2.3 在 `nestjs/README.md` 加 3～5 行：如何 seed、如何给 Admin 联调

### M3 · Admin Nest 客户端与登录（Q-01 / Q-07）

- [ ] A3.1 新增 `src/service/request/nest.ts`：2xx 成功、`transform` 为 `response.data`；**不改** `request/shared.ts`
- [ ] A3.2 HTTP 401：`POST /auth/refresh` → 更新 `token`/`refreshToken` 并重放；失败 `resetStore`
- [ ] A3.3 env：`VITE_NEST_BASE_URL`；开发 `VITE_HTTP_PROXY=Y` 时走 `/proxy-nest`（增量改 `proxy.ts` 或 other service）
- [ ] A3.4 `auth.ts`：`VITE_AUTH_MOCK=N` 时登录/刷新/me 打 Nest，并映射到现有 `LoginToken`/`UserInfo`（技术设计 §4.1）
- [ ] A3.5 存储 Nest `refreshToken`；登出尽量调 `/auth/logout`
- [ ] A3.6 `VITE_AUTH_MOCK=Y` 时登录仍 mock（不阻塞无后端的壳开发）

### M4 · 用户管理页（UC-01～08、UC-12）

- [ ] A4.1 `service/api/admin-users.ts` + `typings/api/admin-users.d.ts`，经 `service/api/index.ts` 导出
- [ ] A4.2 `views/manage/user/index.vue`：`JQCustomPage` + `JQSearch` + `JQDataTable`；无 PageMenu Tab
- [ ] A4.3 新建/编辑用 `JQDialogForm`（`:close-on-click-modal="false"`）；重置密码独立弹窗；启停 `MessageBox` 确认
- [ ] A4.4 错误用接口 `message`/`code` 提示；页面无 `console.log`；不引入 `PRIV`/`v-auth` 业务树
- [ ] A4.5 i18n：`route.manage` / `route.manage_user` + `page.manage.user`（至少 `zh-cn`）；不展示性别/手机
- [ ] A4.6 `pnpm gen-route`（或 dev 热生成）后侧栏出现「用户管理」

### M5 · 联调与文档（AC 收口）

- [ ] T5.1 种子 admin 登录 Admin（`VITE_AUTH_MOCK=N`）→ 列表/筛选/分页
- [ ] T5.2 创建用户后可用新账号登录 Nest；禁用不登录；启用/激活后可登录
- [ ] T5.3 重置密码后旧 refresh 失效；改角色立即影响 `/admin/users` 权限
- [ ] T5.4 禁自己、降最后 admin 被拒绝
- [ ] T5.5 普通 `user` JWT 调管理接口 403；菜单仍可见（stub，AC-10）
- [ ] T5.6 Admin `README` 补：接 Nest 的 env、代理、seed 依赖；`pnpm typecheck` 尽量通过
- [ ] T5.7 实现阶段写 `admin/docs/memory/执行日志-用户管理.md`（用户明确要求开发时）

### M6 · Could（不阻塞 MVP）

- [ ] A6.1 `VITE_AUTH_MOCK=Y` 时用户列表走 mock-handlers（UC-15）

### 不在本计划（Won't）

- 物理删除、导出、RBAC 菜单裁剪、`plan`、Electron 用户管理、改全局 `shared.ts`、Nest 包 `{code,data}`

```text
N0.* ──► N1.* ──► N2.*
              │
              └──► A3.* ──► A4.* ──► T5.*
                              │
```

## 6. 风险与缓冲

| 风险 | 缓冲 | 应对 |
|------|------|------|
| 误用全局 request，Nest 200 被当成失败 | +0.3d | T 门禁：用户 API 只走 `nest.ts`；code review 搜 `fetchLogin` 旧路径 |
| e2e 内存 Prisma mock 缺 `updateMany`/count | +0.3d | N1.9 优先补 mock 行为再写用例 |
| Vite 代理漏改导致 CORS/404 | +0.2d | A3.3 与 Nest CORS 双保险 |
| 登录映射漏字段导致 store 空白 | +0.2d | 对照技术设计 §4.1 表；`initUserInfo` 走 `/auth/me` |
| 最后 admin 用例与并发创建竞态 | 低 | 本期单人后台可接受；计数在事务内读 |

**对外承诺：** 3～4.5 人天外再预留 **+0.5 人天**。
