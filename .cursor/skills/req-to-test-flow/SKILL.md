# 需求到自测全流程

## 约定

- 源需求：`docs/requirements/需求-{名称}.md`（或用户 @ 引用）
- 产出（与 `docs-process` 一致）：

| 步骤 | 路径 |
|------|------|
| 1 梳理版 | `docs/detail/需求-{名称}-梳理版.md` |
| 2 技术设计 | `docs/design/技术设计-{名称}.md` |
| 3 开发计划 | `docs/plan/开发计划-{名称}.md` |
| 4 自测方案 | `docs/test/自测方案-{名称}.md` |

- Mock：`docs/test/mock-{名称}.json`（可选）
- 执行日志：`docs/memory/执行日志-{名称}.md`（实现阶段追加）
- **封装优先**：UI 优先 `src/components/`（尤其 `custom/`）
- **文档阶段禁止写业务代码**（`docs-process`）；实现须用户明确要求

## 流程（严格 1→2→3→4；默认一次只做当前步）

1. **梳理需求** → detail 梳理版（定位、用例、In/Out、MoSCoW、待澄清、验收）
2. **技术设计** → 架构、模块、接口、风险、与用例追溯
3. **开发计划** → 里程碑、可勾选任务、依赖、估时
4. **自测方案** → 范围、用例表、通过标准；可选 Mock
5. **实现**（用户明确要求时）：按 plan 任务编码；**禁止自动 commit**，仅提示建议 message；写执行日志；提醒按自测方案验证

不确定点先反问（`ask-before-acting`）。权限按模板 stub，勿设计半套 privilege。

## 执行日志格式（实现完成后追加）

```markdown
## 执行记录 YYYY-MM-DD HH:mm

- **阶段**：按开发计划实现
- **计划文档**：`docs/plan/开发计划-{名称}.md`
- **完成任务**：T1, T2, …
- **实现摘要**：（与回复一致）
- **涉及文件**：…
- **Commit**：已提示用户提交（建议：`feat: {名称} 按开发计划实现`）
---
```
